上下文压缩（Context Compaction）综述

问题背景

大语言模型（LLM）在推理时受限于固定的上下文窗口和 O(n^2) 的注意力复杂度。随着 Agent 多轮交互、RAG 多文档拼接、长文档理解等场景兴起，有效上下文不断膨胀——推理成本急剧上升，"lost in the middle" 导致性能下降，Agent 更面临上下文溢出后无法继续工作的根本性问题。上下文压缩（Context Compaction / Prompt Compression） 试图在不丢失关键信息的前提下，将已有上下文压缩为更紧凑的表示。

本综述涵盖 50 篇论文，围绕一个核心 formulation：prefix → compact → suffix PPL / agent continuation reward。

七条技术路线

路线 A：硬文本压缩（Hard Text Compression）

输出仍为自然语言或删减后的 token，可直接喂 closed API，工业上最容易落地。

演化脉络：Selective Context (2023) → LLMLingua 系列 (2023–2024) → RECOMP / CompAct (2024) → Nano-Capsulator (2024)

  • Selective Context 开创了基于 self-information 的 token/句子删除范式——无需训练，pure heuristic
  • LLMLingua 引入小模型 PPL 引导的粗到细 token 剪枝，成为工业标准 baseline；LongLLMLingua 加入 query-aware 重排序，缓解 lost-in-the-middle；LLMLingua-2 用 GPT-4 蒸馏为 token 分类器，速度提升数量级
  • RECOMP 首次在 RAG 中同时训练 extractive 和 abstractive 压缩器
  • CompAct 引入 active compression——迭代压缩时跟踪"还缺什么信息"
  • Nano-Capsulator 把压缩目标设为生成自然语言 capsule，通过 RL（utility + length reward）训练，可跨 LLM 迁移

路线 B：软/潜空间压缩（Soft/Latent Compression）

输出是 soft token、summary vector、memory slot 或 embedding。效率高，但通常要改模型接口。

演化脉络：Gist Tokens (2023) → AutoCompressor (2023) → ICAE (2024) → 500xCompressor (2024) → Activation Beacon (2024)

  • Gist Tokens 通过修改 attention mask 将 instruction 压缩为 1 个 token，建立"让模型自己做压缩器"的范式
  • AutoCompressor 推广到多段长文档，summary vector 可递归累积——最贴近 prefix → compress → continuation PPL 的数学直觉
  • ICAE 增加 autoencoding 训练目标（先恢复原文，再 finetune）；500xCompressor 改用 KV 值传递，将比率推至 500x
  • Activation Beacon 在 KV cache 层做在线渐进压缩，4K→400K
  • RAG 方向：xRAG（1 token/doc）、COCOM（context embedding）、QGC（query-guided）、LLoCO（离线压缩+LoRA 在线适配）

路线 C：RL 训练的压缩（RL-Trained Compression）

用下游任务 reward 优化压缩策略，和 suffix-PPL reward 最兼容。

  • PCRL 首创 RL + 离散 token 删除，reward = 下游 perf + 长度，可跨 LLM 迁移
  • TACO-RL 在 LLMLingua-style encoder 上加 task-aware RL reward，task metric 提升 45–189%
  • RLPF 最接近"prediction feedback"思路——用冻结 LLM 的下游预测质量作为 reward 训练 text summarizer，无需 reference summary

路线 D：Agent RL 压缩（Agent RL Compaction）

把摘要作为 agent state 的一部分，在 rollout 里训练。最适合 long-horizon agent compaction。

  • SUPO 把 summarization 放进多轮 RL rollout，end-to-end 训练
  • ReSum 周期性生成 reasoning-state summary + GRPO 训练
  • MemAgent RL 训练 agent 用固定长度 NL memory 覆写——8K→3.5M 近无损外推
  • ACON 发现 naive RL 代价太高，改用 NL-gradient prompt optimization + 蒸馏
  • Memory-R1 把 ADD/UPDATE/DELETE/retrieve 当 RL action，PPO/GRPO 优化
  • AgeMem 统一 LTM/STM 管理为 tool-based action，三阶段渐进 RL

路线 E：Agent 记忆机制（Agent Memory）

通过 heuristic 或 prompt-only 方式管理 agent 记忆，不涉及 RL 训练。

  • MemGPT 把 LLM 上下文当 RAM，外部存储当硬盘，OS 式分页
  • Recursive-Summary 最简单的 baseline：prompt LLM 递归生成摘要
  • Generative Agents 层级反思：从 memory stream 递归总结出高级 insight
  • RMM 前瞻式摘要 + 回顾式 RL 优化检索
  • SUMER 关键反面证据：RL 训练的 search-over-raw-memory 胜过压缩

路线 F：记忆架构（Memory Architecture）

通过 KV/cache/external memory/recurrent memory 延长有效上下文。

  • Compressive Transformer (2020) 奠基思想：旧 memory 压缩而非丢弃
  • RMT 系列 (2022–2023)：recurrent memory token 跨段传递，线性复杂度扩展至 2M token
  • Memorizing Transformer：非压缩路线——kNN 检索过去 KV
  • Infini-attention：在每个 attention block 内加 bounded compressive memory，流式处理无限输入
  • FINCH：prompt-guided KV cache 选择，93x 压缩
  • LongNet：dilated attention，架构级对比方案

路线 G：部署与评估（Serving / Evaluation）

关注 compaction 触发、并行化、延迟、摘要体积控制、验证信号。

  • Parallel Compaction (2026)：block-wise 并行压缩 + volume control，解决"压缩卡住 agent"和"摘要长度不可控"两大痛点
  • Trajectory Validation (2026)：用后续轨迹能否接上来验证压缩质量——与 suffix-PPL 思路高度一致

核心权衡

  1. 压缩率 vs 信息保真度：500xCompressor 证实压缩率与信息损失呈幂律关系
  2. Query-agnostic vs Query-guided：前者支持离线预压缩、一次压缩多次复用；后者高压缩率下效果更好
  3. Soft token vs 硬文本：soft token 信息密度高但不可解释、不能跨模型；硬文本可解释、可喂 API，但压缩率受限
  4. 在线 vs 离线：Activation Beacon 适合流式场景，LLoCO 适合文档库预处理
  5. Heuristic vs RL：heuristic（LLMLingua 系列）快但 task-agnostic；RL（PCRL/TACO-RL/MemAgent）与下游对齐但训练成本高
  6. 压缩 vs 检索：SUMER 证明在某些场景下，RL 训练的 search-over-raw-memory 胜过压缩——compaction 并非万能

研究空白

  • 跨模型迁移：soft token 方案普遍绑定特定 LLM
  • 累积误差：多轮 agent 场景下压缩误差的级联传播尚无系统研究
  • 可控压缩：用户无法指定保留哪些信息维度（事实 vs 推理链 vs 约束）
  • 统一评估：缺乏跨方法、跨场景的统一压缩质量度量
  • 安全性：AgeMem 发现 RL 学到的遗忘行为可能丢弃 safety-critical 信息

Prompt Compression for Large Language Models: A Survey

会议: NAACL 2025
作者: Wenxuan Li, Yufei Cui, Keming Lu, Bowen Yang, Dayiheng Liu, Junyang Lin (Shanghai Jiao Tong University / Alibaba)

注意：本目录 raw/ 中的 TeX 源码和图片来自另一篇论文（Benchmarking Function Hook Latency in Cloud-Native Environments），与本 survey 不匹配。以下内容基于 paper.pdf 撰写。

问题动机

随着 LLM 能力的提升，prompt engineering 技术（ICL、CoT、RAG 等）依赖越来越长的 prompt 来获取更好性能。但长 prompt 带来高推理成本（API 按 token 收费、推理延迟增加）和上下文窗口限制（超过模型最大长度）。Prompt Compression 旨在将 prompt 缩短的同时保持 LLM 输出质量。

这篇 survey 系统梳理了 prompt compression 领域的方法体系，提出了一个完整的分类法，覆盖从硬文本压缩到软提示压缩的各类技术。

核心想法

将 prompt compression 统一到一个框架下，按压缩输出形式分为两大类：

  1. Hard Prompt Compression：输出仍是可读的自然语言文本
  2. Soft Prompt Compression：输出是连续向量表示（soft tokens / memory tokens）

方法细节

分类体系

Survey 将 prompt compression 方法分为以下层次：

1. Hard Prompt Compression（硬文本压缩）

输出为自然语言 token 序列，可直接作为 LLM 输入。

1.1 Extractive 方法：从原始 prompt 中选择保留哪些 token/句子/段落

  • 基于信息熵：利用 perplexity 或 self-information 衡量 token 重要性

    • Selective Context：用 self-information I(x_i) = -\log p(x_i|x_{<i}) 过滤低信息量 token
    • LLMLingua：引入 budget controller + 迭代 token 级压缩
    • LongLLMLingua：加入 question-aware 的 contrastive perplexity

  • 基于学习的分类器：训练模型判断 token/句子的保留与否

    • LLMLingua-2：token 分类模型，通过 GPT-4 蒸馏获取标签
    • AdaComp：句子级 BERT 分类器，用 LLM 反馈构建训练数据
    • CPC：context-aware sentence encoding，句子级打分

  • 基于检索相似度：

    • RECOMP (extractive)：dual-encoder 模型选择最相关句子

1.2 Abstractive 方法：生成新的压缩文本

  • RECOMP (abstractive)：encoder-decoder 生成查询相关摘要
  • CompAct：迭代式主动压缩，逐步融合多文档信息
  • Nano-Capsulator：端到端 seq2seq 压缩，KL 对齐训练

2. Soft Prompt Compression（软提示压缩）

将长上下文压缩为固定数量的连续向量（soft tokens / memory tokens），不可读但可直接输入 Transformer。

  • Gisting：在 prompt 末尾添加 <gist> token，通过训练使其隐状态"吸收"整段 prompt 信息
  • AutoCompressors / ICAE：自回归地将长上下文压缩为 summary vectors
  • Nugget：学习选择性地将某些 token 的表示作为"信息金块"

统一形式化

设原始 prompt 为 \bm{x} = (x_1, \dots, x_L)，压缩后为 \widetilde{\bm{x}}，LLM 为 \mathcal{M}。

Extractive 目标：选择 token 子集

\widetilde{\bm{x}} = \{x_i \mid m_i = 1\}, \quad m_i \in \{0, 1\}
\min_{\bm{m}} D_\text{KL}(P_\mathcal{M}(\cdot|\bm{x}) \| P_\mathcal{M}(\cdot|\widetilde{\bm{x}})) \quad \text{s.t.} \; \|\bm{m}\|_0 \leq \tau L

Abstractive 目标：生成新文本

\widetilde{\bm{x}} = \mathcal{C}(\bm{x}), \quad |\widetilde{\bm{x}}| \leq \tau L

Soft Prompt 目标：学习连续表示

\widetilde{\bm{h}} = f_\theta(\bm{x}) \in \mathbb{R}^{k \times d}

其中 k \ll L 是压缩后的 token 数，d 是隐层维度。

评估维度

Survey 梳理了四个评估维度：

  1. 任务性能保持率：压缩前后的性能差距
  2. 压缩比：1/\tau = L / |\widetilde{\bm{x}}|
  3. 延迟/加速比：压缩后的端到端推理加速
  4. 泛化性：跨任务、跨 LLM 的迁移能力

关键结果

Survey 通过对比实验和文献分析得出以下关键发现：

  • 信息熵方法（LLMLingua 系列）在通用性上最强，但压缩本身有计算开销
  • 学习分类方法（LLMLingua-2）在速度上大幅领先，但依赖训练数据质量
  • Abstractive 方法可读性最好但有 hallucination 风险
  • Soft Prompt 方法压缩比最高（可达 50-100x），但需要修改模型且不可解释
  • 在高压缩比（>10x）下，soft prompt 方法显著优于 hard prompt 方法
  • 在中低压缩比（2-5x）下，hard prompt 方法的性能-成本 trade-off 更优

局限与延伸阅读

Survey 识别的开放问题：

  1. 压缩与任务的耦合：task-agnostic vs task-aware 的 trade-off 尚无定论
  2. 评估标准化：缺少统一的压缩质量评估基准
  3. 多模态扩展：当前方法主要面向文本，视觉/音频等模态的 prompt 压缩尚未充分探索
  4. 理论基础：压缩信息量与下游任务性能的理论关系不清晰

  • 信息熵路线：Selective Context → LLMLingua → LongLLMLingua
  • 分类器路线：LLMLingua-2、AdaComp、CPC
  • 生成式路线：RECOMP、CompAct、Nano-Capsulator
  • 语义压缩路线：Semantic Compression

RECOMP: Improving Retrieval-Augmented LMs with Compression and Selective Augmentation

会议: ICLR 2024
作者: Fangyuan Xu, Weijia Shi, Eunsol Choi (UT Austin / University of Washington)

问题动机

Retrieval-Augmented Generation (RAG) 通过检索外部文档为 LLM 提供事实知识，但存在两个关键问题：(1) 检索到的文档通常包含大量与问题无关的冗余信息，增加输入长度和推理成本；(2) 低质量检索结果（irrelevant 或 misleading）可能反而损害 LLM 性能。现有方法要么将整篇文档拼接（wasteful），要么做简单截断（lossy），缺乏选择性地提取和压缩检索内容的能力。

核心想法

训练专门的 compressor 模型来压缩检索文档，提出两种互补策略：(1) Extractive Compressor 从检索文档中选出最有用的句子；(2) Abstractive Compressor 将多个文档的信息综合为一段简洁摘要。两者都只在压缩后的内容确实有帮助时才将其添加到 prompt 中（selective augmentation）。

方法细节

训练 Pipeline

对于每个 query q 和检索到的文档集合 D = \{d_1, \dots, d_n\}，compressor 生成压缩摘要 s，拼接到 LLM prompt 中：

\hat{a} = \text{LLM}(s \oplus q)

训练目标是让 s 帮助 LLM 正确回答 q。

Extractive Compressor

从每篇文档中选取最有价值的句子。训练一个 dual-encoder 模型：

\text{score}(q, s_i) = \text{Enc}_q(q)^\top \text{Enc}_d(s_i)

其中 s_i 是候选句子。训练时用 contrastive learning：

\mathcal{L}_{\text{ext}} = -\log \frac{\exp(\text{score}(q, s^+)/\tau)}{\sum_j \exp(\text{score}(q, s_j)/\tau)}

正例 s^+ 通过两个标准选择：(1) 拼接后 LLM 能回答正确；(2) 与 gold answer 有高 ROUGE overlap。

Abstractive Compressor

用 encoder-decoder 模型（基于 T5）将多文档内容综合为一段自然语言摘要。训练数据通过蒸馏获得：

  1. 用 GPT-3 对检索文档生成多个候选摘要
  2. 用 NLI 模型过滤掉与 gold answer 矛盾的摘要
  3. 选择能让 LLM 正确回答的摘要作为训练目标
\mathcal{L}_{\text{abs}} = -\sum_t \log p(s_t \mid s_{<t}, q, D)

Selective Augmentation

当压缩后的摘要不够自信时，选择不添加任何检索内容（仅用原始 query），避免引入噪声。具体实现：

  • Extractive：当所有句子的 score 低于阈值时不添加
  • Abstractive：当生成的摘要似然低于阈值时不添加

关键结果

  • NQ (Open-domain QA)：Extractive compressor 将平均 prompt 长度从 ~2000 tokens 压缩到 ~90 tokens，EM 提升 2-5 个点

  • TriviaQA：Abstractive compressor 在 6x 压缩下与全文档 RAG 性能持平

  • Language Modeling：在 Wikitext-103 上，Extractive compressor 以 35% 的 token 达到与全文档相同的 perplexity

  • Selective augmentation 策略在所有设置下一致优于 always-augment，证明了过滤不良检索结果的价值

局限与延伸阅读

局限：

  1. Abstractive compressor 依赖 GPT-3 蒸馏数据，训练成本较高
  2. 压缩质量与下游 LLM 绑定——为 LLaMA 训练的 compressor 可能不适用于 GPT-4
  3. Extractive compressor 的 dual-encoder 结构限制了跨句子的交互建模

延伸阅读：

  • CompAct（2407.09014）：迭代式主动压缩，支持多轮文档融合和 early termination
  • Nano-Capsulator（2311.04991）：端到端生成式压缩，保持自然语言可读性
  • Semantic Compression（2312.09571）：用语义单元替代 token 做上下文窗口扩展

LLMLingua: Compressing Prompts for Accelerated Inference of Large Language Models

会议: EMNLP 2023
作者: Huiqiang Jiang, Qianhui Wu, Chin-Yew Lin, Yuqing Yang, Lili Qiu (Microsoft)

问题动机

现代 LLM prompting 技术（如 CoT、ICL、RAG）依赖大量上下文 token 来获取好的性能，但冗长的 prompt 带来高昂的推理成本。Selective Context 等方法简单地用自信息做 token 过滤，但存在两个问题：(1) prompt 中不同组件（instruction / demonstrations / question）的重要程度不同，需要差异化压缩；(2) 基于 perplexity 的独立 token 过滤在高压缩比下丢失语义严重，因为它假设 token 之间条件独立。

核心想法

提出粗到细（coarse-to-fine）的 prompt 压缩框架：Budget Controller 在 demonstration 级别做粗粒度压缩 + 差异化预算分配，然后 迭代 token 级压缩（ITPC） 在细粒度上基于 perplexity 逐段压缩以缓解独立性假设带来的误差，最后通过 分布对齐 缩小小模型与目标 LLM 之间的分布差距。

方法细节

问题形式化

Prompt \bm{x} = (\bm{x}^{\text{ins}}, \bm{x}^{\text{dems}}, \bm{x}^{\text{que}})，包含 instruction、demonstrations 和 question。压缩目标：

\min_{\widetilde{\bm{x}}, \tau} \text{KL}(P(\widetilde{\bm{x}}_G|\widetilde{\bm{x}}), P(\bm{x}_G|\bm{x}))

其中 \tau = \widetilde{L}/L 是压缩率。

Budget Controller

为不同组件分配差异化压缩比：instruction 和 question 直接影响生成结果，分配更多预算（更低压缩比）；demonstrations 信息冗余度高，分配更少预算。

Demonstrations 的压缩率：

\tau_{\text{dems}} = \frac{\tau L - (\tau_{\text{ins}} L_{\text{ins}} + \tau_{\text{que}} L_{\text{que}})}{L_{\text{dems}}}

粗粒度压缩：用小模型（GPT-2/LLaMA）计算每个 demonstration 的 perplexity，按 perplexity 降序选取 demonstration，直到 token 总数达到预算上限。剩余预算回分给 instruction 和 question：

\Delta\tau = \frac{k \cdot \tau_{\text{dems}} L_{\text{dems}} - \widetilde{L}_{\mathcal{D}}}{L_{\text{ins}} + L_{\text{que}}}

迭代 Token 级压缩 (ITPC)

直接用 perplexity 过滤 token 面临条件独立假设问题——删掉的 token 和保留的 token 实际上有相互依赖关系。ITPC 将 prompt 分段处理：

p(\bm{\widetilde{s}}_j) \approx \prod_{i} p(s_{j,i} \mid s_{j,<i}, \bm{\widetilde{s}}_{<j})

每一段的压缩结果会拼接到下一段前面，提供更准确的条件概率估计。每段根据所属组件使用不同的压缩阈值 \gamma_j，perplexity 高于阈值的 token 被保留：

\bm{\widetilde{s}}_j = \{s_{j,i} \mid p(s_{j,i}) > \gamma_j\}

分布对齐

用目标 LLM 生成的数据对小语言模型做 instruction tuning，缩小两者的 token 概率分布差距：

\min_{\bm{\theta}_s} \mathbb{E}\left[\frac{1}{N}\sum_{i=1}^N \mathcal{L}(\bm{x}_i, \bm{y}_{i,\text{LLM}}; \bm{\theta}_{\mathcal{M}_s})\right]

关键结果

  • 在 GSM8K（数学推理）上达到 20x 压缩，仅损失 1.3% 准确率
  • 在 BBH 上 1/\tau = 4 时性能几乎无损
  • 端到端推理加速 1.7-5.7x，GPU 显存最高降低 62%
  • 相比 Selective Context，在同压缩比下一致性优于后者

局限与延伸阅读

局限：

  1. 压缩后的 prompt 是 token 子序列，可读性差
  2. perplexity 是经验指标，未针对压缩目标显式优化
  3. 需要 GPU 运行小语言模型，对轻量部署有要求

延伸阅读：

  • LongLLMLingua（2310.06839）：在长上下文场景下引入 question-aware 的粗细粒度压缩
  • LLMLingua-2（2403.12968）：将 perplexity 替换为 token 分类任务，用数据蒸馏显式学习压缩目标
  • Selective Context（2310.06201）：LLMLingua 的前置工作和基线方法

Selective Context: Compressing Context to Enhance Inference Efficiency of Large Language Models

会议: EMNLP 2023
作者: Yucheng Li, Bo Dong, Chenghua Lin, Frank Guerin (University of Surrey / University of Manchester)

问题动机

LLM 处理长文档时面临两个核心挑战：(1) Transformer 的自注意力机制导致内存和计算随上下文长度呈二次增长；(2) 预训练时的固定上下文窗口限制了处理更长文本的能力。现有方法主要从模型架构层面（稀疏注意力、局部密集注意力）或软提示蒸馏的角度切入，但缺少一个模型无关的、直接作用于输入文本本身的冗余消除方案。

自然语言天生包含大量冗余：既有语言本身的重复性（如对话中的重复表述），也有与 LLM 预训练数据重叠的信息——这些冗余对人类理解有帮助，但对 LLM 而言是不必要的计算开销。

核心想法

利用**自信息（self-information / surprisal）**衡量输入上下文中每个词汇单元的信息量：自信息低的内容说明 LLM 本身就能预测到，是冗余的，可以安全删除；自信息高的内容则是关键信息，需要保留。

方法细节

自信息计算

给定上下文 C = (x_0, x_1, \dots, x_n)，使用因果语言模型计算每个 token 的自信息：

I(x_i) = -\log_2 P(x_i \mid x_0, x_1, \dots, x_{i-1})

自信息衡量一个 token 的"惊奇度"：罕见事件传递更多信息，因此自信息更高。

词汇单元合并

直接在 token 级别做过滤可能导致上下文过于碎片化。因此 Selective Context 支持在三个粒度上进行过滤：

  • Token 级：直接使用 token 的自信息
  • 短语级：利用 spaCy 的名词短语合并
  • 句子级：利用 NLTK 句子分词器

利用自信息的可加性，词汇单元 u = (x_t, \dots, x_{t+\alpha}) 的自信息为：

I(u) = \sum_{i=t}^{\alpha} I(x_i)

基于百分位的自适应过滤

对所有词汇单元按自信息降序排列，计算第 p 百分位阈值 I_p，只保留自信息 \geq I_p 的单元：

C' = \{U_i \mid I(U_i) \geq I_p, \; 1 \leq i \leq n\}

p 值直接控制压缩比例——例如 p=50 意味着过滤掉约一半的词汇单元。

整体流程

  1. 用小型因果语言模型（如 GPT-2 curie、LLaMA-7B）逐句计算自信息
  2. 按指定粒度合并 token 为词汇单元
  3. 基于百分位阈值过滤，生成压缩后的 Selective Context

关键结果

  • 在 arXiv 论文、BBC 新闻、ShareGPT 对话三个数据集上测试，覆盖摘要、问答、上下文重建、对话四个任务
  • 压缩比 0.5 时（去掉 50% 内容），BERTScore 仅下降 0.023，faithfulness 仅下降 0.038
  • 实际推理中实现 36% 显存降低、32% 推理时间加速
  • 短语级过滤效果最优，优于 token 级和句子级

  • 经指令微调的模型（Vicuna）比原始模型（LLaMA）在 Selective Context 下表现更鲁棒

局限与延伸阅读

局限：

  1. 短语边界检测依赖 spaCy 的名词短语分词，未涵盖动词短语
  2. 最优压缩百分位因任务和上下文而异，缺少自动确定最优阈值的机制

延伸阅读：

  • LLMLingua（2310.05736）：在 Selective Context 基础上引入 budget controller 和迭代 token 级压缩，支持更高压缩比
  • LLMLingua-2（2403.12968）：将 Selective Context 的信息熵指标替换为显式学习的 token 分类目标，获得更好的压缩-性能平衡
  • Selective Context 是最具代表性的 task-agnostic 硬文本压缩 baseline，后续几乎所有 prompt compression 工作都将其作为对比方法

LongLLMLingua: Accelerating and Enhancing LLMs in Long Context Scenarios via Prompt Compression

会议: ACL 2024
作者: Huiqiang Jiang, Qianhui Wu, Xufang Luo, Dongsheng Li, Chin-Yew Lin, Yuqing Yang, Lili Qiu (Microsoft)

问题动机

在长上下文场景（如 RAG 多文档问答）中，LLM 面临三大问题：(1) "Lost in the Middle" 现象——LLM 倾向于关注 prompt 开头和结尾的信息，中间部分的关键信息容易被忽略；(2) 原始 LLMLingua 在 token 级压缩时不感知 question，无法有效保留与问题相关的关键信息；(3) 所有文档使用相同压缩比，未考虑不同文档与问题的关联度差异。

核心想法

在 LLMLingua 的框架上，引入 question-aware 的粗细粒度压缩策略：用 question 条件下的文档 perplexity 做粗粒度文档筛选，用 **contrastive perplexity（对比困惑度）**做细粒度 token 选择，并通过文档重排和自适应压缩比分配解决 "Lost in the Middle" 问题。

方法细节

问题形式化

Prompt \mathbf{x} = (\mathbf{x}^{\text{ins}}, \mathbf{x}^{\text{doc}}_1, \dots, \mathbf{x}^{\text{doc}}_K, \mathbf{x}^{\text{que}})。优化目标：

\min_{\widetilde{\mathbf{x}}} D_\phi(\mathbf{y}, \widetilde{\mathbf{y}}) + \lambda \|\widetilde{\mathbf{x}}\|_0

Question-Aware 粗粒度压缩

用 question 在不同文档条件下的 perplexity 来衡量文档重要性——如果某文档让 question 的 perplexity 更低，说明该文档包含更多与问题相关的信息：

r_k = -\frac{1}{N_c} \sum_i^{N_c} \log p(x_i^{\text{que,restrict}} \mid \mathbf{x}_k^{\text{doc}})

其中 \mathbf{x}^{\text{restrict}} 是一个约束性陈述（"We can get the answer to this question in the given documents"），起正则化作用。

实验表明，这种 question-conditioned perplexity 在文档召回率上超过了 BM25、OpenAI Embedding、Cohere-Rerank 等所有传统和神经检索方法。

Contrastive Perplexity（对比困惑度）

在细粒度 token 压缩中，简单地将 question 拼接在文档前面计算 perplexity 会降低相关 token 的困惑度，反而使其更难与无关 token 区分。LongLLMLingua 提出用 perplexity 差值——即 question 带来的分布偏移——来衡量 token 与 question 的关联：

s_i = \text{perplexity}(x_i \mid x_{<i}) - \text{perplexity}(x_i \mid x^{\text{que}}, x_{<i})

这等价于条件逐点互信息（conditional PMI）。对比困惑度高的 token 更可能与 question 相关。

文档重排

利用粗粒度压缩得到的重要性分数 r_k，对文档进行重排，将最重要的文档放在 prompt 的开头和结尾，缓解 "Lost in the Middle" 问题。

自适应压缩比

用线性调度器根据文档重要性排名分配不同压缩比：

\tau_k^{\text{doc}} = \max\left(\min\left(\left(1 - \frac{2I(r_k)}{K'}\right)\delta\tau + \tau^{\text{doc}}, 1\right), 0\right)

重要文档分配更低压缩比（保留更多 token），不重要文档压缩更多。

子序列恢复 (Subsequence Recovery)

LLM 生成时常复制 prompt 中的实体（人名、地名等），token 级压缩可能导致这些实体不完整。通过在原始 prompt 中查找 LLM 回复中子序列的最长匹配，将压缩后的实体恢复为原始完整形式。

关键结果

  • 在 NaturalQuestions 多文档 QA 上，4x 压缩比下 性能提升 17.1%（相比原始 prompt）
  • 在 LongBench 上一致优于 LLMLingua 和 Selective Context
  • 粗粒度压缩的文档召回率超过所有传统检索方法
  • 端到端推理成本降低至原来的 1/4~1/6

局限与延伸阅读

局限：

  1. 粗细粒度压缩均需运行小语言模型，推理延迟较高
  2. Contrastive perplexity 需要对每个文档做两次前向传播
  3. 仍然是 task-aware 方法，每个新 query 需要重新压缩

延伸阅读：

  • LLMLingua-2（2403.12968）：用 token 分类模型替代 perplexity 计算，速度提升 3-6x
  • CPC（2409.01227）：用 context-aware sentence encoder 做句子级压缩，速度比 LongLLMLingua 快 10.93x
  • CompAct（2407.09014）：用迭代压缩策略主动融合多文档信息

Nano-Capsulator: Learning to Compress Prompt in Natural Language

会议: NAACL 2024 (Findings)
作者: Bohao Yang, Haodi Zhang, Deng Cai (The Chinese University of Hong Kong)

注意：本目录 raw/ 中的 TeX 源码和图片来自另一篇论文（continual test-time adaptation），与 Nano-Capsulator 不匹配。以下内容基于 paper.pdf 撰写。

问题动机

现有 prompt 压缩方法（LLMLingua、Selective Context 等）基于 token 过滤——从原始 prompt 中选择 token 子集保留。这种方式有两个根本问题：(1) 可读性差：token 子序列不是自然语言，人类无法检查压缩结果的正确性；(2) 信息密度有限：只能保留原文中存在的 token，无法用更紧凑的表达重新组织信息。生成式（abstractive）压缩可以产生可读的自然语言，但现有方法（如 RECOMP）依赖任务特定的训练，难以泛化。

核心想法

训练一个轻量级的端到端 seq2seq 压缩模型（Nano-Capsulator），输入原始 prompt 文本，输出自然语言形式的压缩版本。关键创新是训练策略：利用 LLM 的输出分布作为监督信号，通过 KL 散度最小化 使压缩文本在 LLM 视角下与原始文本等价。

方法细节

模型架构

Nano-Capsulator 基于小型 encoder-decoder 模型（如 BART-large 或 T5），接收原始 prompt \bm{x} 并生成压缩后的自然语言文本 \widetilde{\bm{x}}：

\widetilde{\bm{x}} = \text{NanoCap}(\bm{x})

训练目标

训练分两个阶段：

阶段一：预热训练
使用标准的 seq2seq 摘要目标进行预热，让模型学会基本的文本压缩能力：

\mathcal{L}_{\text{warm}} = -\sum_t \log p(\widetilde{x}_t \mid \widetilde{x}_{<t}, \bm{x})

阶段二：KL 对齐训练
核心训练阶段。将原始 prompt \bm{x} 和压缩 prompt \widetilde{\bm{x}} 分别输入 LLM，最小化两者输出分布的 KL 散度：

\mathcal{L}_{\text{KL}} = \text{KL}\left(P_{\text{LLM}}(\cdot \mid \bm{x}) \;\|\; P_{\text{LLM}}(\cdot \mid \widetilde{\bm{x}})\right)

为了让梯度能从 LLM 回传到 compressor（跨越离散文本生成的不可微问题），使用 Gumbel-Softmax 或 straight-through estimator 近似。

压缩比控制

通过限制生成序列的最大长度来控制压缩比。训练时使用多种目标长度，使模型学会在不同压缩率下工作。

自然语言输出

与 LLMLingua 等 token 过滤方法不同，Nano-Capsulator 输出的是完整、可读的自然语言文本。这使得：

  • 压缩结果可被人类审查和验证
  • 更好地保留语义连贯性
  • 可以用比原文更紧凑的表达来传达相同信息

关键结果

  • 在多个 NLU 和 NLG 任务上（包括摘要、QA、对话），4x 压缩比下 性能保持在原始 prompt 的 90-95%
  • 生成式压缩的 faithfulness 显著优于 token 过滤方法
  • 压缩文本的 人类可读性 评分远高于 LLMLingua 类方法
  • 模型参数量小（BART-large ~400M），推理延迟可接受

局限与延伸阅读

局限：

  1. KL 对齐训练需要 LLM 参与前向传播，训练成本较高
  2. Gumbel-Softmax 近似引入训练不稳定性
  3. 生成式压缩有 hallucination 风险——可能引入原文不存在的信息
  4. 当前版本仍然是 task-agnostic 训练，在特定任务上可能不如 task-aware 方法

延伸阅读：

  • RECOMP（2310.04408）：另一种 abstractive compressor，通过 GPT-3 蒸馏训练
  • CompAct（2407.09014）：迭代式压缩，每步输出自然语言摘要
  • Semantic Compression（2312.09571）：用语义单元做上下文压缩，也保持可读性
  • LLMLingua-2（2403.12968）：对比方法，token 分类思路但输出仍为 token 子序列

Extending Context Window of Large Language Models via Semantic Compression

会议: ACL 2024 (Findings)
作者: Weizhi Fei, Xueyan Niu, Pingyi Zhou, Lu Hou, Bo Bai, Lei Deng, Wei Han (Huawei / Tsinghua)

问题动机

LLM 的上下文窗口有固定长度限制（如 4K / 8K tokens），面对超长文本时被迫截断，丢失关键信息。现有的长上下文方案分两类：(1) 架构修改（ALiBi、RoPE 外推等）需要重新训练或微调，成本高；(2) Token 级压缩（LLMLingua 等）丢弃 token 导致语义碎片化。缺少一种在语义层面做压缩的方法，能在保持语义完整性的同时将上下文"塞进"有限窗口。

核心想法

将长文本分为多个段，每一段用一个小型语言模型生成语义压缩（Semantic Compression） 的摘要表示，然后将压缩段的摘要拼接起来作为"虚拟上下文窗口扩展"。关键设计：利用自回归的段间迭代压缩，让后续段的压缩感知到前面段的信息。

方法细节

方法概述

给定超长文本 X = (x_1, x_2, \dots, x_T)，窗口大小 W，将其分为 n 段 \{S_1, S_2, \dots, S_n\}，每段长度约 W/r（r 为压缩比）。

对每一段 S_i，用一个训练好的压缩模型 \mathcal{C} 生成压缩表示 \hat{S}_i：

\hat{S}_i = \mathcal{C}(S_i, \hat{S}_{<i})

其中 \hat{S}_{<i} 表示前面所有段的压缩结果。最终的有效上下文为所有压缩段的拼接：\hat{X} = [\hat{S}_1, \hat{S}_2, \dots, \hat{S}_n]，长度远小于原始 T。

压缩模型训练

压缩模型 \mathcal{C} 基于小型 LM（如 GPT-2），用 重构损失 训练：

\mathcal{L} = -\sum_{t} \log P_{\text{LLM}}(x_t \mid \hat{S}_{<\text{seg}(t)}, x_{<t \text{ in seg}})

即训练目标是让压缩后的上下文能帮助 LLM 正确预测原始文本的下一个 token。

Passkey Retrieval 测试

为验证长距离信息保留能力，使用 Passkey Retrieval 任务——在超长文本中随机位置插入一个 5 位数字，要求模型在文末找回这个数字：

与 token 级压缩的区别

特性 Token 级压缩（LLMLingua 等） Semantic Compression
压缩单元 单个 token 语义段
输出形式 Token 子序列 生成式摘要
语义完整性 碎片化 保持段内语义
跨段信息 无感知 自回归迭代传递

推理流程

推理时：

  1. 将长文本分段
  2. 对前 n-1 段依次压缩，将压缩结果放入上下文
  3. 最后一段保持原始文本，与所有压缩段拼接后送入 LLM

关键结果

  • Passkey Retrieval：在 8x 上下文扩展（4K → 32K）下达到 100% 准确率
  • 语言建模（Perplexity）：在 PG-19 等长文本数据集上，Semantic Compression 的 perplexity 优于截断策略

  • 4x 压缩下，perplexity 仅比使用完整上下文高 0.5-1.0
  • 与 LLMLingua 对比，在同等压缩比下语义完整性更好

局限与延伸阅读

局限：

  1. 压缩模型需要额外训练，与目标 LLM 绑定
  2. 段间迭代压缩引入顺序依赖，无法并行
  3. 压缩是有损的，对精确引用或逐字复制任务可能损害较大
  4. 当前仅验证了语言建模和 passkey 任务，缺少下游 NLU 评测

延伸阅读：

  • LLMLingua（2310.05736）：token 级压缩方法，速度更快但语义碎片化
  • Nano-Capsulator（2311.04991）：端到端生成式压缩，类似思路但面向 prompt 而非上下文窗口
  • CEPE / AutoCompressors：用 soft prompt 做上下文压缩的相关工作

LLMLingua-2: Data Distillation for Efficient and Faithful Task-Agnostic Prompt Compression

会议: ACL 2024 (Findings)
作者: Zhuoshi Pan, Qianhui Wu, Huiqiang Jiang, Menglin Xia, Xufang Luo, Jue Zhang, Qingwei Lin, Victor Rühle, Yuqing Yang, Chin-Yew Lin, H. Vicky Zhao, Lili Qiu, Dongmei Zhang (Microsoft / Tsinghua)

问题动机

LLMLingua 系列方法用小语言模型的 perplexity 作为 token 重要性指标做 prompt 压缩，但存在根本性缺陷：

  1. 信息瓶颈：perplexity 反映的是 token 在训练语料上的可预测性（I(x_i) = -\log p(x_i \mid x_{<i})），而非 token 对下游任务的重要性——常见的功能词 perplexity 低但可能承载关键语义关系
  2. 压缩目标不一致：压缩阶段用小模型的 perplexity 排序，推理阶段用大模型理解压缩结果，两者分布不同
  3. 可读性差：token 级子序列压缩产生碎片化文本，严重损害 faithfulness

核心想法

将 prompt 压缩重新定义为一个 token 分类任务（保留 / 丢弃），并通过数据蒸馏从 GPT-4 获取训练标签——让 GPT-4 自行压缩文本，将原始文本与压缩结果对齐得到 token 级标注，然后训练一个轻量 BERT 分类器来高速压缩。

方法细节

数据蒸馏：从 GPT-4 获取压缩标签

  1. 获取压缩文本：给 GPT-4 提供原始文本和 task-agnostic 的压缩指令，让其输出压缩版本
  2. Token 级对齐：将原始文本和 GPT-4 压缩结果进行 word-level 对齐，出现在压缩结果中的 token 标记为"保留"（y_i = 1），否则标记为"丢弃"（y_i = 0）。对齐使用贪心最长匹配策略
  3. 最终得到 token 级二分类标签 \{(\bm{x}, \bm{y}) \mid y_i \in \{0, 1\}\}

Token 分类模型

使用 Transformer encoder（如 XLM-RoBERTa 或 mBERT）作为分类器。对输入序列 \bm{x} = (x_1, \dots, x_N)：

\bm{h} = \text{Transformer}(\bm{x}) \in \mathbb{R}^{N \times d}
p(y_i = 1 \mid \bm{x}) = \sigma(\bm{W} \bm{h}_i + \bm{b})

训练目标为交叉熵损失：

\mathcal{L} = -\frac{1}{N} \sum_{i=1}^N \left[y_i \log p_i + (1-y_i)\log(1-p_i)\right]

推理时通过调整分类阈值（而非固定为 0.5）来控制压缩率：保留 p(y_i=1|\bm{x}) 排名在前 \tau \cdot N 的 token，\tau 为目标压缩率。

压缩策略：保留原始 token

与 LLMLingua 相同，压缩结果是原始 token 的子序列，但 LLMLingua-2 通过显式的 token 分类学习到更好的保留决策，产生的压缩文本可读性更高。

关键结果

  • MeetingBank（摘要）：2x 压缩下 ROUGE-1/2/L 分别达到 24.0/6.2/15.4，超越未压缩 baseline
  • LongBench：涵盖 QA、摘要、few-shot 和代码任务，在 2-5x 压缩比下一致优于 LLMLingua 和 LongLLMLingua
  • 速度：基于 XLM-RoBERTa-large 的分类器比 LLMLingua（基于 LLaMA-7B 的 perplexity 计算）快 3-6 倍
  • Faithfulness：GPTScore 评测显示，LLMLingua-2 压缩文本的 faithfulness 显著高于 perplexity 方法

局限与延伸阅读

局限：

  1. 数据蒸馏依赖 GPT-4 的压缩标注，标注成本较高
  2. Task-agnostic 压缩策略在特定任务上可能不如 question-aware 方法（如 LongLLMLingua）
  3. 依赖 word-level 对齐算法的准确性

延伸阅读：

  • LLMLingua（2310.05736）：前置工作，基于 perplexity 的 token 过滤
  • RECOMP（2310.04408）：另一种压缩方法，训练专门的 abstractive/extractive 压缩器
  • AdaComp（2409.01579）：用 BERT 分类器做句子级自适应压缩，也是 token/sentence 分类思路

CompAct: Compressing Retrieved Documents Actively for Question Answering

会议: EMNLP 2024
作者: Chanwoong Yoon, Taewhoo Lee, Hyeon Hwang, Minbyul Jeong, Jaewoo Kang (Korea University)

问题动机

RAG 系统中，检索到的多个文档往往包含大量冗余甚至不相关的信息。现有压缩方法存在两个局限：(1) 一次性处理所有文档，无法在获取足够信息后提前终止；(2) 多文档的信息分散，简单的单次压缩难以有效跨文档整合与问题相关的证据。

一个关键观察是：在问答任务中，不同问题需要的文档数量差异很大——简单问题可能只需 1-2 篇，复杂多跳问题可能需要 5 篇以上。统一的压缩策略无法适应这种差异。

核心想法

提出迭代式主动压缩框架：将检索文档分成多个段（segment），每轮处理一个段并与之前的压缩结果融合更新，同时由模型自主判断是否已收集到足够信息以提前终止（early termination）。这使压缩过程具有自适应性——根据问题复杂度动态决定处理文档数量。

方法细节

迭代式主动压缩

给定 question q 和检索文档 D_k = \{d_1, \dots, d_k\}，先将文档分组：

S_t = \{d_{(t-1) \times j+1}, \dots, d_{(t-1) \times j + j}\}

其中 j 是每次处理的文档数。每一步的压缩过程为：

C_t, E_t = \pi(q, S_t, C_{t-1})

C_t 是当前步的压缩上下文，E_t 是评估结果。C_t 包含了从第 1 步到第 t 步的所有关键信息，作为下一步的输入。

三步式压缩

每个迭代步骤中，模型执行三个子任务：

  1. 句子级选择：分析新段 S_t 中的句子，结合已有压缩上下文 C_{t-1}，选出与问题相关的句子
  2. Query-focused 压缩：将选出的句子压缩为简洁的上下文（显式限制模型不能做假设或直接回答，只做信息压缩）
  3. 终止判断：模型评估当前压缩上下文是否足以回答问题，输出 [COMPLETE] 或 [INCOMPLETE]

Early Termination

Early Termination 带来三重好处：

  • 阻止冗余信息进入压缩上下文
  • 避免不必要的迭代，降低计算开销
  • 动态适应问题复杂度

数据集构建

使用 GPT-4 对 NaturalQuestions、HotpotQA、MuSiQue 三个数据集构建训练数据。考虑两种场景：

  • Realistic：使用真实检索结果
  • Distractor：包含 gold 文档，用于收集更多 [COMPLETE] 终止样例

最终训练集约 28k 实例。模型基于 Flan-T5-XL 微调。

关键结果

  • NQ：CompAct + GPT-3.5 比不压缩的 GPT-3.5（使用完整文档）提升 3.9 个 EM 点
  • HotpotQA：CompAct 在 F1 上比 RECOMP 高 5-10 个百分点
  • MuSiQue（多跳）：CompAct 在该挑战性数据集上的优势更加明显
  • 压缩效率：平均将 5 篇文档（~700 tokens）压缩为 ~100 tokens 的上下文

  • Early termination 在约 60% 的 NQ 样本上提前终止，节省大量推理成本
  • 与 LLMLingua、RECOMP 等方法对比，CompAct 在所有数据集上一致最优

局限与延伸阅读

局限：

  1. 训练依赖 GPT-4 构建的标注数据
  2. 迭代处理引入额外延迟，不适合超低延迟场景
  3. 文档分组的大小 j 是固定超参数

延伸阅读：

  • RECOMP（2310.04408）：CompAct 的主要 baseline，extractive + abstractive 一次性压缩
  • LLMLingua-2（2403.12968）：token 级分类压缩，速度更快但不做跨文档融合
  • Nano-Capsulator（2311.04991）：端到端生成式压缩，同样保持自然语言形式

CPC: Compressing Long Context for Enhancing RAG with Context-Aware Sentence Encoding

会议: AAAI 2025
作者: Shinon Matsui, Tatsuya Ishigaki, Gaku Morio, Terufumi Morishita, Hiroshi Noji, Hiroya Takamura, Ichiro Kobayashi (Ochanomizu University / Hitachi)

问题动机

现有 prompt 压缩方法在速度和精度之间存在矛盾：(1) LLMLingua/LongLLMLingua 等基于 perplexity 的方法需要用 LLaMA-7B 级别的模型做多次前向传播，压缩本身就很慢——LongLLMLingua 在 10K tokens 输入上压缩就需要数十秒；(2) 快速的方法（如 Selective Context）精度不足；(3) 句子级方法（如 RECOMP extractive）使用独立编码，缺乏句子间的上下文交互信息——一个句子的重要性往往取决于它在文档中的位置和周围内容。

核心想法

提出 Context-aware Sentence Encoding 方法：用 BERT 级别的 encoder 同时编码整个文档的所有句子（而非独立编码每个句子），使每个句子的重要性打分能感知到全局上下文。结合 query-aware 的打分机制和高效的句子级压缩，实现比 LongLLMLingua 快 10.93x 的压缩速度，同时保持甚至超越其精度。

方法细节

Context-Aware Sentence Encoding

给定文档 D = (s_1, s_2, \dots, s_n)（n 个句子）和 query q，将所有句子与 query 一起送入 BERT encoder：

\mathbf{H} = \text{BERT}([q; s_1; s_2; \dots; s_n])

每个句子 s_i 的表示取其对应区间内所有 token 的平均池化：

\mathbf{h}_{s_i} = \text{MeanPool}(\mathbf{H}[\text{start}_i : \text{end}_i])

关键优势：由于 BERT 的自注意力机制，\mathbf{h}_{s_i} 天然包含了 query 信息和其他句子的上下文信息。

句子重要性打分

用一个可学习的线性层对句子表示打分：

\text{score}(s_i) = \mathbf{w}^\top \mathbf{h}_{s_i} + b

保留得分最高的 k 个句子（k 由目标压缩率决定）：

D' = \text{TopK}(\{s_i\}_{i=1}^n, k), \quad k = \lfloor \tau \cdot n \rfloor

对比学习训练

使用 contrastive learning 训练 encoder 和打分函数。对于每个 query q：

  • 正例：包含 answer 信息的句子（通过 NLI 或 string matching 识别）
  • 负例：同文档中的无关句子

训练损失：

\mathcal{L} = -\log \frac{\exp(\text{score}(s^+) / \tau_T)}{\sum_{j} \exp(\text{score}(s_j) / \tau_T)}

其中 \tau_T 是温度参数。

上图展示了 context-aware encoding 的效果：同一句子在不同文档上下文中的重要性得分不同，说明模型能根据全局信息动态调整判断。

关键结果

  • NaturalQuestions：CPC + GPT-3.5 的 EM 与 LongLLMLingua 持平，但压缩速度快 10.93 倍

  • 在 10K tokens 输入上：CPC 压缩耗时 ~0.3s，LongLLMLingua 耗时 ~3.3s
  • HotpotQA：CPC 在 F1 上优于 LLMLingua-2 约 2 个百分点
  • 句子级压缩使输出保持可读性，优于 token 级方法

  • Context-aware encoding 相比 independent encoding（如 RECOMP extractive）在所有数据集上一致提升 1-3 个 EM 点
  • 使用 DeBERTa-base（~140M 参数）即可达到良好效果，远轻于 LLaMA-7B

局限与延伸阅读

局限：

  1. 句子级压缩粒度较粗，无法做 token 级的精细控制
  2. BERT 的输入长度限制（512 tokens）对超长文档需要分块处理
  3. 句子分割质量影响压缩效果

延伸阅读：

  • LongLLMLingua（2310.06839）：CPC 的主要对比方法，token 级 question-aware 压缩
  • AdaComp（2409.01579）：同样做句子级分类，但使用 cross-encoding 和 LLM 反馈训练
  • RECOMP（2310.04408）：独立句子编码的 extractive compressor，CPC 的 ablation baseline
  • LLMLingua-2（2403.12968）：token 级分类，粒度互补

AdaComp: Extractive Context Compression with Adaptive Predictor Training for Retrieval-Augmented Large Language Models

来源: arXiv 2024
作者: Qianchi Zhang, Hainan Zhang, Liang Pang, Hongwei Zheng, Zhiming Zheng (Beihang University / CAS)

问题动机

RAG 系统中检索到的文档包含大量与 query 无关的噪声信息。现有的 extractive 压缩方法主要基于 perplexity（LLMLingua）或简单的二分类器（LLMLingua-2），但存在一个核心问题：压缩决策应该是自适应的——不同 query 对不同文档、不同句子的信息需求差异巨大，而固定压缩率或固定阈值的方法无法适应这种差异。此外，现有方法缺乏有效的负例构建策略来训练压缩判别器。

核心想法

训练一个 adaptive predictor（基于 BERT 的句子级分类器），用 LLM 反馈 自动构建正负例训练数据——通过对比"包含某句子"和"不包含某句子"时 LLM 的回答质量变化来判断句子重要性。推理时根据 query 和文档内容动态决定保留哪些句子。

方法细节

训练数据构建

对每个训练样本 (q, D, a)（query、检索文档集、gold answer），构造句子级标注：

  1. 初始检测：将文档 D 分成句子 \{s_1, \dots, s_n\}，逐句送入 LLM 与 query 一起判断：
\text{score}(s_i) = f_{\text{LLM}}(q, s_i)

用 LLM 判断该句子是否有助于回答问题，获取初始候选集 S^+。

  1. 质量验证：通过 leave-one-out 策略验证每个候选句子的必要性：
\Delta(s_i) = f_{\text{LLM}}(q, S^+ \setminus \{s_i\}) - f_{\text{LLM}}(q, S^+)

如果移除 s_i 后 LLM 回答质量下降（\Delta(s_i) > 0），说明 s_i 确实重要。

  1. 负例构建：从 S^+ \setminus \{s_i\}（即不包含目标句子的正例集合）中选择混淆度高的句子作为负例，而非简单随机采样。

Adaptive Predictor

基于 BERT 的分类模型，输入 query q 和句子 s_i，输出保留概率：

p(y_i = 1 \mid q, s_i) = \sigma(\text{MLP}(\text{BERT}([q; s_i])))

训练目标：

\mathcal{L} = -\frac{1}{N}\sum_{i=1}^N \left[y_i \log p_i + (1-y_i)\log(1-p_i)\right]

推理时自适应压缩

推理时不使用固定压缩率，而是为每个句子独立预测：

\text{compressed}(D) = \{s_i \mid p(y_i=1 \mid q, s_i) > \theta\}

阈值 \theta 在验证集上调优。不同 query 可能保留不同数量的句子，实现真正的自适应压缩。

关键结果

  • NaturalQuestions：AdaComp + GPT-3.5 在 EM 上比 LLMLingua-2 高 3.2 个点
  • TriviaQA：压缩后性能与使用完整文档持平，同时减少 60-70% 的 token
  • HotpotQA / MuSiQue：在多跳推理任务上显著优于 Selective Context 和 LLMLingua

  • 与固定压缩率方法对比，自适应策略在简单 query 上压缩更多、复杂 query 上保留更多，整体效率更优
  • 句子级压缩粒度在可读性和信息密度之间取得较好平衡

局限与延伸阅读

局限：

  1. LLM 反馈构建训练数据的成本较高（需要多次 LLM 调用）
  2. 句子级粒度可能不够细——同一句子中可能只有部分信息与 query 相关
  3. BERT 分类器的交叉编码（cross-encoding）方式效率低于 dual-encoder

延伸阅读：

  • LLMLingua-2（2403.12968）：token 级分类，粒度更细但不做 query-aware
  • CPC（2409.01227）：context-aware sentence encoding，同样做句子级压缩但速度更快
  • CompAct（2407.09014）：迭代式主动压缩，另一种自适应策略
  • RECOMP（2310.04408）：extractive + abstractive 双路径压缩

Familiarity-Aware Evidence Compression for Retrieval-Augmented Generation

EMNLP 2024 Findings · Dongwon Jung, Qin Liu, Tenghao Huang, Ben Zhou, Muhao Chen (UC Davis, USC, ASU)

问题动机

RAG 系统在面对多文档问答等复杂任务时，检索到的证据往往包含不一致或无关信息，干扰 LM 的下游任务。现有的证据压缩方法（如 LongLLMLingua、RECOMP）用一个独立的压缩模型将文档摘要后再喂给目标模型，但压缩模型与目标模型之间存在 内部知识差异和 prompt 偏好差异——压缩出来的证据对目标模型来说可能是"陌生"的，导致目标模型要么过度依赖自身参数知识，要么盲目信任不相关的检索证据。

核心想法

将目标模型的 困惑度（perplexity） 作为"熟悉度"信号引入证据压缩过程：在解码时对压缩模型和目标模型的 token 概率做加权集成，使生成的压缩证据同时保留关键检索信息且对目标模型更友好，并自然地融合参数知识与非参数知识。

方法细节

基本流程

给定 k 篇检索证据 D=\{d_1,\ldots,d_k\} 和查询 x，先用压缩模型自回归生成摘要 c：

P_{\text{comp}}(c \mid \mathcal{C}_{\text{comp}}) = \prod_{i=1}^{|c|} P_{\text{comp}}(c_i \mid \mathcal{C}_{\text{comp}}, c_{<i})

同时，目标模型被指示仅根据查询生成有助于回答问题的上下文（不参考文档）：

P_{\text{tar}}(c \mid \mathcal{C}_{\text{gen}}) = \prod_{i=1}^{|c|} P_{\text{tar}}(c_i \mid \mathcal{C}_{\text{gen}}, c_{<i})

Ensemble Decoding

FaviComp 在每个解码步选择使两个模型联合概率最大的 token：

c_i = \arg\max_{c'_i \in V} \bigl(\alpha \cdot \log P_{\text{tar}}(c'_i \mid \mathcal{C}_{\text{gen}}, c_{<i}) + (1-\alpha) \cdot \log P_{\text{comp}}(c'_i \mid \mathcal{C}_{\text{comp}}, c_{<i})\bigr)

其中 \alpha 为集成系数，控制参数知识与检索知识的权衡。当 \alpha=0 退化为普通摘要，\alpha=1 退化为纯参数知识生成。

这一设计有两个优势：

  1. 降低目标模型困惑度——上采权那些目标模型更"熟悉"的 token，使压缩结果更易被利用
  2. 融合参数与非参数知识——当压缩模型对下一 token 不确定时，目标模型的参数知识可以补充缺失信息

关键结果

  • 在 5 个 open-domain QA 数据集上，FaviComp 一致超越所有基线方法，准确率最高提升 28.1%
  • 最佳性能出现在 \alpha=0.5，即等权集成两个模型时
  • 当 \alpha < 0.5，性能随困惑度降低而提升（与 prior work 一致）；当 \alpha > 0.5，虽困惑度继续降低但因缺少证据知识导致性能下降

  • 在证据不包含答案的样本（Hits=0）上，FaviComp 显著优于其他方法——说明它能有效利用参数知识
  • 在证据包含答案的样本（Hits=1）上，FaviComp 与其他方法相当——说明它没有牺牲证据利用能力
  • 简单拼接参数知识和非参数知识（concatenation）反而不如单独用非参数知识，而 FaviComp 通过解码时融合实现了有效协同

局限与延伸阅读

  • FaviComp 是 inference-time 方法（无需训练），但需要同时运行两个 LM 的前向传播，推理成本较高
  • 方法假设压缩模型和目标模型共享词表，跨架构适用性需进一步验证
  • 与本主题其他方法的关系：属于硬文本压缩（abstractive）路线，与 RECOMP、CompAct 同类但引入了目标模型感知；与 soft token 方法（ICAE、AutoCompressor）正交

Learning to Compress Prompts with Gist Tokens

NeurIPS 2023 · Jesse Mu, Xiang Lisa Li, Noah Goodman (Stanford)

问题动机

LLM 的 prompt（如系统指令）在每次推理时都会被重复编码，占用宝贵的上下文窗口并带来二次复杂度的计算开销。Finetuning/distillation 可以去掉 prompt，但需要为每个任务重新训练模型。如何在不重新训练的前提下，将任意 prompt 压缩到极少量 token 以实现缓存复用？

核心想法

在 instruction tuning 时，只需修改 Transformer 的 attention mask，在 prompt 后插入少量 gist token，强制 prompt 之后的 token 不能 attend 到 prompt 本身——模型被迫将 prompt 信息压缩进 gist token 的 KV activation 中。这一方法 不增加任何额外训练成本。

方法细节

Gist Masking

向词表中添加一个 gist token g，在 prompt 和 input 之间插入 k 个拷贝：(t, g_1, \dots, g_k, x)。修改 attention mask 使得：

  • Decoder-only 模型（如 LLaMA）：在因果 mask 的基础上，遮蔽左下角——input/output token 不能 attend 到 prompt token，但可以 attend gist token

  • Encoder-decoder 模型（如 T5）：在 encoder 中防止 input attend prompt 且防止 prompt attend input；在 decoder 的 cross-attention 中防止 attend prompt

从 Context Distillation 视角理解

标准 context distillation 为单个任务 t 学习一个不需要 prompt 的模型 p^t_{\text{CD}}。Gisting 将其推广为跨任务的 meta-distillation：

\mathcal{L}_G(p_G, T) = \mathbb{E}_{t \sim T, x} \left[ D_{\text{KL}}\bigl(p_{\text{LM}}(y \mid t, x) \| p_G(y \mid G(t), x)\bigr) \right]

其中 G(t) 是 gist token 上的 KV activation——相当于用 LM 自身做 HyperNetwork，零样本预测任务的压缩前缀。

  • Human evaluation 显示 gist 模型与 positive control 的 win rate 接近 50%（LLaMA 52.3%，FLAN-T5 40.6%）
  • ChatGPT 评估与人类评估高度一致（Cohen's \kappa \approx 0.29），可作为可靠的自动评估手段

  • Gisting 在压缩时不可避免地丢失指令中的具体细节（如需要逐字复制的类别名），以及可能出现 runaway generation
  • 仅在 instruction 级别（通常 ~20 token）验证；对更长上下文的压缩效果有待探索
  • 后续工作 ICAE、AutoCompressor、Activation Beacon 都在此基础上扩展到更长上下文的压缩
  • 与 Compressive Transformer 的区别：gisting 用 LM 自身 attention 而非单独的压缩函数，且通过标准 LM loss 训练而非辅助重建损失

Adapting LLMs to Compress Contexts (AutoCompressor)

EMNLP 2023 · Alexis Chevalier, Alexander Wettig, Anirudh Ajith, Danqi Chen (Princeton)

问题动机

Transformer 语言模型的上下文窗口有限（如 2048 或 4096 token），无法有效处理长文档。暴力扩展窗口面临 O(n^2) 的 attention 计算和内存瓶颈。Compressive Transformer 等先行工作需要设计单独的压缩函数，而现有 soft prompt 方法只能压缩固定文本，不能泛化到新上下文。

核心想法

让语言模型自身学会将长上下文分段压缩为少量 summary vector（软 token），并将这些 summary 级联传递给后续段落——模型既当压缩器又当消费者，整个过程端到端用标准语言建模损失训练。

方法细节

Summary Vector 机制

将长文档 d 拆分为等长段落 \{s_1, s_2, \ldots, s_n\}，每段末尾追加 m 个可学习的 summary token \sigma。模型处理完一段后，取 summary token 对应的最终隐状态作为该段的 summary vector：

\mathbf{e}_j = \text{LM}([\mathbf{e}_{<j}; s_j; \sigma])[-m:]

其中 \mathbf{e}_{<j} 是前面所有段落累积的 summary vector。

Summary 累积（Accumulation）

关键设计：第 j 段的输入不仅包含当前文本 s_j，还包含所有之前段落的 summary \mathbf{e}_1, \ldots, \mathbf{e}_{j-1}——形成一个不断增长的压缩记忆。为保持每段输入长度可控，summary vector 只做 cross-attention，不增加自注意力开销。

训练

仅使用标准因果语言建模损失，在所有段落上联合 backprop：

\mathcal{L} = -\sum_{j=1}^{n} \sum_{i=1}^{|s_j|} \log P(s_{j,i} \mid \mathbf{e}_{<j}, s_{j,<i})

实际训练中使用 randomized segment length 和 stop-gradient 策略来控制内存并增强泛化。

位置编码处理

Summary vector 被赋予与前一段最后一个 token 相同的位置 ID——告诉模型这些 summary 是"过去"的压缩表示。

关键结果

  • 在语言建模任务上，AutoCompressor（OPT-2.7B + 50 summary vectors × 6 段）使困惑度从 14.57 降至 11.45
  • 在 passage retrieval 任务上，直接用 summary vector 做文档嵌入，在 KILT 基准上召回率与 Contriever 相当：KILT-NQ R@5 = 54.5 vs Contriever 53.4
  • 每段仅用 50 个 summary vector，实现约 30x 压缩（假设每段 1500 token）

  • 消融实验表明：更多 summary token 有帮助但边际递减，accumulation 比只用上一段的 summary 效果明显更好
  • stop-gradient 策略关键：全部 backprop 到第一段反而导致训练不稳定

局限与延伸阅读

  • Summary vector 是不可解释的——无法人工检视压缩后保留了哪些信息
  • 训练需要 segment-level 的 backpropagation-through-time，对长序列仍有内存压力
  • 与 Gist Tokens 的区别：AutoCompressor 面向任意长上下文的多段累积压缩，而 Gist Tokens 面向短 instruction 的单次压缩
  • 后续工作 ICAE 进一步引入了显式的 autoencoding 目标来提升压缩质量

In-context Autoencoder for Context Compression in a Large Language Model

ICLR 2024 · Tao Ge, Jing Hu, Lei Wang, Xun Wang, Si-Qing Chen, Furu Wei (Microsoft Research)

问题动机

长上下文处理时 LLM 的 KV cache 带来巨大内存和计算开销。已有压缩方法（如 Gist Tokens）只在 instruction 级别验证，对文档级长上下文的压缩效果不佳。关键问题是：如何在保持信息完整性的同时将数百甚至数千 token 的上下文压缩到少量 "memory slot" 中？

核心想法

受自编码器启发，将上下文压缩问题建模为 autoencoding：用 LLM 本身（加上轻量 LoRA adapter）作为 encoder，将原始上下文压缩为固定数量的 memory slot，再用相同 LLM（不同 LoRA）作为 decoder 从 memory slot 恢复上下文——两阶段训练：先预训练 autoencoding 能力，再在下游任务上微调。

方法细节

编码器

在原始上下文 C 后追加 \ell_{\text{mem}} 个特殊 memory token \langle\text{mem}\rangle，用配有 LoRA_{\text{AE}} 的 LLM 编码：

\mathbf{M} = \text{LLM}_{\text{LoRA}_\text{AE}}([C; \langle\text{mem}\rangle_1, \ldots, \langle\text{mem}\rangle_{\ell_\text{mem}}])[-\ell_\text{mem}:]

memory slot \mathbf{M} 即为上下文的压缩表示。

解码器

将 memory slot 作为 soft prefix，拼接到新 prompt 前，用配有 LoRA_{\text{FT}} 的 LLM 进行下游推理：

P(y \mid \mathbf{M}, x) = \text{LLM}_{\text{LoRA}_\text{FT}}([\mathbf{M}; x; y])

两阶段训练

预训练：同时优化 autoencoding loss \mathcal{L}_{\text{ae}}（从 memory slot 恢复原文）和 language modeling loss \mathcal{L}_{\text{lm}}（利用 memory slot 续写）：

\mathcal{L}_{\text{pretrain}} = \mathcal{L}_{\text{ae}} + \mathcal{L}_{\text{lm}}

微调：固定 LoRA_{\text{AE}}，只训练 LoRA_{\text{FT}}，在具体任务数据上对齐压缩表示与下游需求。

多段拼接

ICAE 天然支持将多段文档分别压缩后拼接 memory slot：

\mathbf{M}_{\text{all}} = [\mathbf{M}_1; \mathbf{M}_2; \ldots; \mathbf{M}_k]

关键结果

  • 基于 Llama-7B，使用 128 个 memory slot 压缩最多 512 token 的上下文，实现 4x 压缩率
  • 在 text reconstruction 任务上，BLEU 分数远超 Gist Tokens 和 AutoCompressor
  • 在 NLU 任务上（NLI、summarization、QA），微调后的 ICAE 接近使用完整上下文的性能
  • GPT-4 评估在生成任务上 win rate 接近 50%
  • 推理加速：128 memory slot 处理 512 token，KV cache 减少约 4\times

局限与延伸阅读

  • 当前压缩比仅 4x，远低于后续工作 500xCompressor 的极端压缩
  • 两阶段训练流程较为复杂，且 encoder 和 decoder 使用不同 LoRA——部署需维护两套 adapter
  • 仅在 Llama-7B 上验证，未测试更大模型
  • 与 AutoCompressor 的关键区别：ICAE 引入了显式的 autoencoding 训练目标（恢复原文），而 AutoCompressor 仅用 LM loss
  • 后续 500xCompressor 在此基础上通过 embedding 空间映射实现了更极端的压缩

Soaring from 4K to 400K: Extending LLM's Context with Activation Beacon

arXiv 2024 · Peitian Zhang, Zheng Liu, Shitao Xiao, Ninglu Shao, Qiwei Ye, Zhicheng Dou (Renmin University, BAAI)

问题动机

LLM 的有效上下文长度被其训练时的窗口大小严格限制（如 LLaMA-2 仅 4K）。现有方法要么通过位置外推（如 PI、NTK-aware）修改位置编码但丢失细粒度信息，要么通过 token dropping/eviction 丢弃 KV cache 造成不可逆信息损失。需要一种方法能在保持细粒度信息的同时将上下文窗口扩展 100 倍。

核心想法

在 LLM 的正常上下文流中插入 Activation Beacon 特殊 token，让它们通过注意力机制将相邻 raw token 的激活信息凝缩到自身——处理完一个窗口后丢弃 raw token 的 KV cache，只保留 beacon 的 KV cache，实现渐进式压缩。

方法细节

Beacon Token

在每个窗口（大小 w）的末尾插入少量 beacon token。每个 beacon 负责凝缩 r（compression ratio）个 raw token 的信息。Beacon 的 attention 遵循以下规则：

  • Raw token：按标准因果 attention 只 attend 到之前的 raw token 和 beacon（保持原始 LLM 行为不变）
  • Beacon token：attend 到它负责压缩的 raw token 区间以及之前所有 beacon

这样 raw token 的生成完全不受 beacon 干扰，而 beacon 则作为信息汇聚点。

渐进式压缩（Stepwise Compression）

  • 第一步：处理窗口 1 的 raw token，beacon 凝缩信息
  • 第二步：丢弃窗口 1 的 raw KV cache，只保留 beacon KV cache
  • 第三步：处理窗口 2（拼接窗口 1 的 beacon + 窗口 2 的 raw token + 窗口 2 的 beacon）
  • 重复上述过程直到所有文本处理完毕

总内存占用从 O(n) 降为 O(w + n/r)。

灵活压缩率

训练时从 \{2, 4, 8, 16, 32, 64, 128\} 中随机采样压缩率，使模型掌握不同粒度的压缩能力。推理时可根据可用内存动态选择压缩率。

训练

仅训练 beacon 相关参数（beacon embedding、attention 中与 beacon 相关的投影矩阵），LLM 原始参数冻结。使用标准语言建模损失，在长文档上训练。

关键结果

  • 成功将 LLaMA-2-7B 的有效上下文从 4K 扩展到 400K
  • 在 Needle-in-a-Haystack 测试中，100K 长度下达到接近 100% 的检索准确率
  • 在 LongBench 上超越所有全注意力方法（包括 PI、NTK-aware），且推理速度更快
  • 相比 full attention 基线，内存节省超 80%，同时困惑度几乎无损
方法 有效上下文 内存 (100K) PPL (100K)
Full Attention 4K OOM N/A
StreamingLLM 无限 固定 极高
Activation Beacon 400K ~20% of full 低

局限与延伸阅读

  • 渐进式压缩是单向的——后续窗口无法修正前面窗口的压缩错误
  • 较高压缩率（128x）下细粒度信息（如精确数字、人名）仍会丢失
  • 与 Gist Tokens / ICAE 等方法的关键区别：Activation Beacon 是在 KV cache 层面 做在线压缩，不需要预先编码整段文本，更适合流式场景
  • 后续可与 RAG 结合——用 Activation Beacon 压缩长检索上下文

LLoCO: Learning Long Contexts Offline

EMNLP 2024 · Sijun Tan, Xiuyu Li, Shishir Patil, Ziyang Wu, Tianjun Zhang, Kurt Keutzer, Joseph E. Gonzalez, Raluca Ada Popa (UC Berkeley)

问题动机

处理长上下文的主流方案要么需要超长窗口 LLM（如 128K 的 GPT-4），推理成本极高；要么用 RAG 检索相关片段，但受限于 chunk 粒度和检索质量。能否在离线阶段将长上下文预压缩为固定长度表示，推理时直接使用压缩后的上下文，避免每次 query 都重新处理全文？

核心想法

两阶段离线-在线范式：离线用 AutoCompressor 将长上下文压缩为 summary vector，然后用 LoRA 微调一个 LLM 学会利用这些压缩表示完成下游任务。推理时 LLM 仅处理压缩后的固定长度上下文 + 短 query，实现常数级推理成本。

方法细节

离线压缩

使用预训练的 AutoCompressor 将长文档 D（可达数万 token）分段压缩为 summary vector：

\mathbf{S} = \text{AutoCompressor}(D) \in \mathbb{R}^{n_s \times d}

其中 n_s 是 summary vector 数量，d 是隐状态维度。每个 segment 的 summary vector 数量固定，因此总 summary 数量与文档长度成正比但远小于原始 token 数。

在线推理

将 summary vector \mathbf{S} 作为 soft prefix 拼接到 query q 前，用 LoRA 微调的 LLM 生成答案：

P(a \mid D, q) \approx P_{\text{LoRA}}(a \mid \mathbf{S}, q)

LoRA 的角色是弥合 AutoCompressor 的压缩表示与目标 LLM 之间的"表示鸿沟"。

训练

使用 QLoRA（4-bit 量化 + LoRA），训练数据为 (summary vector, query, answer) 三元组：

\mathcal{L} = -\sum_{t=1}^{|a|} \log P_{\text{LoRA}}(a_t \mid \mathbf{S}, q, a_{<t})

由于 summary vector 是离线预计算的，训练和推理时的上下文长度与原文长度无关，仅取决于 summary 数量。

关键结果

  • 基于 Llama-2-7B + AutoCompressor，在长上下文任务上测试
  • 在 Needle-in-a-Haystack 实验中，LLoCO 在单针和多针检索上均达到接近 100% 准确率
  • 压缩率与性能：在 30x 压缩下，性能几乎无损

  • 推理效率：推理 FLOPs 与全文处理相比减少 30x；prefill 延迟下降显著
  • 在 QMSum、QuALITY、QASPER 等长文档 QA/摘要任务上，LLoCO 超越 retrieval-based 方法（如 BM25 + LLM），接近或达到使用全文的 full-context 上限

局限与延伸阅读

  • 依赖 AutoCompressor 的压缩质量——如果压缩丢失了回答所需的信息，LoRA 无法挽回
  • 离线压缩是固定的，无法根据不同 query 动态调整压缩策略——与 query-guided 方法（如 QGC）互补
  • 需要为每个下游任务微调 LoRA，泛化到 zero-shot 场景还需探索
  • 与 AutoCompressor 的关系：LLoCO 是 AutoCompressor 的应用层扩展——AutoCompressor 提供压缩，LLoCO 提供利用压缩的 task adaptation
  • 与 ICAE 的区别：LLoCO 分离了压缩和利用两个阶段，ICAE 用同一模型（不同 LoRA）做这两件事

xRAG: Extreme Context Compression for Retrieval-Augmented Generation with One Token

NeurIPS 2024 · Xin Cheng, Lixin Su, Xin, Baotian Hu, Min Zhang (Harbin Institute of Technology, Shenzhen)

问题动机

RAG 系统通常将检索到的文档以原始文本形式拼接到 prompt 中，当文档数量增多时占据大量上下文窗口，带来高延迟和高计算成本。现有 soft token 压缩方法（如 ICAE、AutoCompressor）虽然能减少 token 数，但仍需多个 soft token（如 128 个），压缩率有限，且压缩后的 token 缺乏语义可解释性。

核心想法

将文档检索嵌入（如 DPR 的 768 维向量）视为一种 "模态"，借鉴多模态 LLM 的做法（如 LLaVA），用一个可训练的 projector 将检索嵌入映射为 LLM 输入空间中的 单个 token——实现极端的 1-token 压缩。

方法细节

架构

xRAG 由三个组件构成：

  1. Dense Retriever（冻结）：给定 query q，检索 top-k 文档 \{d_1, \ldots, d_k\}，为每个文档生成 dense embedding \mathbf{e}_i \in \mathbb{R}^{d_r}
  2. Projector f_\theta（可训练）：将每个检索嵌入 \mathbf{e}_i 映射为 LLM 输入空间的单个向量 \mathbf{v}_i = f_\theta(\mathbf{e}_i) \in \mathbb{R}^{d_m}
  3. LLM（冻结/LoRA 微调）：接收 [\mathbf{v}_1, \ldots, \mathbf{v}_k, \text{query tokens}] 作为输入

生成过程：

P(y \mid q) = \prod_{t=1}^{|y|} P_{\text{LLM}}(y_t \mid f_\theta(\mathbf{e}_1), \ldots, f_\theta(\mathbf{e}_k), q, y_{<t})

训练策略

训练分两步：

  1. Stage 1 — 对齐预训练：用 reading comprehension 数据训练 projector，让 LLM 学会从压缩的文档 embedding 中提取信息
  2. Stage 2 — 指令微调：在下游 QA 数据上进一步微调 projector 和 LLM 的 LoRA

检索调制（Retrieval Modulation）

xRAG 天然支持在推理时通过调节检索文档的数量 k 来平衡效果和效率。由于每个文档只占 1 个 token，即使使用 k=20 也仅增加 20 个 token。

关键结果

  • 基于 Mixtral-8x7B + Contriever，在 6 个 open-domain QA 数据集上
  • xRAG（1 token/doc）在多数任务上与使用完整文本的 RAG 基线效果相当甚至更优
  • 与其他压缩方法的对比：使用 1 个 token 即超越 ICAE 的 128 token、AutoCompressor 的 50 token
  • FLOPs 减少约 3.53x

  • 面对 irrelevant documents 的干扰，xRAG 表现出比 vanilla RAG 更强的鲁棒性——因为 projector 会"过滤"掉不相关文档的信号
  • 在 Mixtral MoE 架构中，xRAG embedding 会激活与正常文本不同的 expert 路由模式

局限与延伸阅读

  • 1 个 token 的极端压缩不可避免地丢失细粒度信息——在需要从文档中提取精确数字、日期的任务上可能不足
  • 依赖高质量的 dense retriever embedding——如果 retriever 质量差，压缩后更难恢复
  • Projector 是 retriever-specific 的——换检索器需要重新训练
  • 与 COCOM 的区别：xRAG 用单个 projector 做一步映射，COCOM 用完整 cross-attention 生成多个 context embedding
  • 与 FaviComp 的区别：xRAG 在 embedding 层融合，FaviComp 在 decoding 层融合

UniICL: An Efficient Unified Framework Unifying Compression, Selection, and Generation

ACL 2025 | Gao et al. (Soochow University, HIT Shenzhen, PolyU)

问题动机

In-context learning (ICL) 通过在输入前拼接若干 demonstration 来提升 LLM 推理能力，但面临两大挑战：

  1. 上下文长度激增：拼接多个 demonstration 会严重增加输入长度，带来硬件负担；
  2. demonstration 质量差：现有基于 off-the-shelf 检索器（如 S-BERT）的选择方法只能找到浅层相关的 demonstration，甚至可能误导模型（如选出标签相反的样例）。

已有的 prompt compression 方法（如 ICAE、AutoCompressor）不区分 demonstration 和 query 地一起压缩，导致 query 信息丢失和性能下降。

核心想法

将 demonstration 压缩、demonstration 选择和最终生成统一到一个框架中。每个 demonstration 独立压缩为 Memory Tokens，利用压缩后的表示在隐空间中度量相似性来选择 demonstration，最后将选中的 Memory Tokens 拼接后送入 LLM 生成回答。整个框架仅需 17M 可训练参数。

方法细节

Demonstration Compression

引入可学习的 Memory Slot \text{[M]} \in \mathbb{R}^d，将 k 个 Memory Slot 附加在每个 demonstration D_i 后面，通过冻结的 Vicuna-7B 前向推理获得 last hidden states：

H^i = f_\theta(D_i^{L_i \times d} \oplus M^{k \times d})

然后通过线性投影层得到 Memory Tokens：

c^i_j = W_p^{d \times d} \cdot h^i_j

Demonstration Selection

利用 Memory Tokens 的平均池化表示计算 query 与 demonstration 之间的余弦相似度：

\bar{C^i} = \frac{1}{k}\sum_{j=1}^k c_j
S_i = \text{cosine\_similarity}(\bar{C_Q}, \bar{C}_D^i)

Generation

将选中的 m 个 demonstration 的 Memory Tokens 水平拼接，与 query 一起输入冻结的 Vicuna 进行自回归生成：

y_i = g_\theta(C^1, ..., C^m; Q; y_{<i})

Training

两阶段训练。第一阶段用语言建模损失训练压缩能力：

\mathcal{L}_{lm} = -\frac{1}{|y|}\sum_{t=0}\log P(y_t|x_u; C; y_{<t})

第二阶段加入对比学习增强选择能力，通过 PPL 变化挖掘正负样本：

\mathcal{L} = \mathcal{L}_{lm} + \mathcal{L}_{ctr}

Demonstration Bank

为避免重复压缩同一 demonstration，UniICL 将压缩结果缓存到 Demonstration Bank (DB) 中，推理时直接复用。

关键结果

  • 在 CoLA、SST-2、IMDb、Arxiv、XSum 等 out-of-domain 数据集上，UniICL 全面超越 Vicuna（直接拼接 demo）、AutoCompressor、LLMLingua、ICAE 等基线。
  • 在 MMLU benchmark 上 5-shot 达到 51.2 平均准确率。
  • 在 MS MARCO 段落排序任务上 MRR@10 达到 31.6（零样本），接近专门的 IR 模型 SIMLM（41.1，有监督）。
  • 12× 压缩下，UniICL 将 demo 数量从 4 扩展到 64（24GB 显存内），而原始 7B 模型在 8-shot 就 OOM。

局限与延伸阅读

  • 目前局限于标准 ICL 范式，未探索 RAG、CoT 等高级 prompting。
  • 受限于硬件，仅在 7B 规模模型上验证。
  • 与 ICAE（同为 soft token 压缩）和 AutoCompressor（循环压缩）形成对比：UniICL 独立压缩 demo 以避免窗口限制，且可训练参数仅 17M（ICAE 70M, AutoCompressor 7B）。
  • 与 LLMLingua 等 extractive 方法互补：UniICL 走 soft prompt 路线，压缩率更高但需模型 embedding 空间。

Query-Guided Compressor (QGC) for LLMs

ACL 2024 · Zhaochen Su, Han Wu, Mingyuan Ma, Liru Qiu, Qian Wang, Xiaoguang Liu (Nankai University)

问题动机

在 RAG 场景中，检索到的文档通常包含大量与 query 无关的信息。现有压缩方法（如 AutoCompressor、ICAE）不感知 query——它们对所有信息等权压缩，在低压缩率下还能保留足够信息，但在高压缩率下会严重丢失与 query 相关的关键信息。预备实验表明：AutoCompressor 在高压缩率下严重丢失关键信息，LongLLMLingua 选出的 token 位置高度集中而非分散在关键信息处。

核心想法

设计 query-guided 的压缩器——以 query 为条件对上下文进行编码和压缩，让模型优先保留与当前问题相关的信息。

方法细节

架构总览

QGC 包含四个模块：

1. Query-Guided Context Encoder

用预训练的 decoder-only LLM（如 LLaMA）作为 encoder，将 query q 和 document d 拼接输入：

\mathbf{H} = \text{LLM}([q; d]) \in \mathbb{R}^{(|q|+|d|) \times d_h}

取 document 部分的隐状态 \mathbf{H}_d——由于因果注意力，\mathbf{H}_d 中的每个位置都已融入了 query 信息。

2. Adaptive Pooling

将 \mathbf{H}_d 通过 adaptive average pooling 压缩到目标长度 n_c：

\mathbf{Z} = \text{AdaptiveAvgPool}(\mathbf{H}_d) \in \mathbb{R}^{n_c \times d_h}

这一步实现了灵活的压缩率：n_c 可在推理时动态设定。

3. Reviewing Mechanism

压缩后的表示通过一层 cross-attention "回看" 原始文档表示，补充池化过程中可能丢失的细节：

\mathbf{Z}' = \text{CrossAttn}(\mathbf{Z}, \mathbf{H}_d, \mathbf{H}_d) + \mathbf{Z}

4. Semantic Alignment

添加一个线性投影层，将 compressor 的输出空间对齐到 target LLM 的输入 embedding 空间：

\mathbf{E}_c = \mathbf{W} \cdot \mathbf{Z}' + \mathbf{b}

训练

端到端训练 compressor（LoRA on encoder + pooling + cross-attention + projection），target LLM 冻结。损失函数：

\mathcal{L} = -\sum_{t=1}^{|a|} \log P_{\text{LLM}}(a_t \mid \mathbf{E}_c, q, a_{<t})

关键结果

  • 基于 LLaMA-2-7B 作为 compressor 和 target LLM，在 NQ、TriviaQA、HotpotQA 上评测
  • QGC 在所有压缩率下一致超越 AutoCompressor、LongLLMLingua 等基线
  • 在 4x 压缩 下：NQ EM 36.0（vs AutoCompressor 30.2，LongLLMLingua 31.8）
  • 在 16x 压缩 下：QGC 仍能保持合理性能，而 AutoCompressor 几乎崩溃

  • 关键信息保留分析：QGC 在各压缩率下关键信息保留率远高于 AutoCompressor 和 LongLLMLingua
  • 推理效率：由于压缩后 token 数减少，QGC 在解码阶段的 throughput 提升显著

局限与延伸阅读

  • Compressor 本身需要处理 full-length 的 query + document，压缩阶段的计算成本并未减少——好处主要在多次推理同一文档或 decoder 端 的加速
  • Query-guided 意味着每换一个 query 就要重新压缩文档——不适合离线预压缩场景（与 LLoCO 形成互补）
  • Adaptive pooling 是一种简单但粗糙的降维方式，可能不如 learned attention pooling
  • 与 COCOM 的异同：两者都用 soft embedding 做 RAG 压缩，但 QGC 显式引入 query guidance 而 COCOM 不区分 query/context
  • 与 FaviComp 的区别：FaviComp 在解码时感知目标模型（familiarity-aware），QGC 在编码时感知 query（query-guided）

Recurrent Context Compression: Efficiently Expanding the Context Window of LLM

arXiv 2024 | Huang et al. (UCAS, CASIA)

问题动机

Transformer LLM 处理长文本时面临两个根本限制：(1) 超出预训练上下文窗口后生成质量急剧下降；(2) KV-Cache 的显存消耗随序列长度线性增长。

现有的上下文压缩方法（如 ICAE）在高压缩率（>8×）下性能大幅下降，且主要在短序列上研究，缺乏对长序列的系统探索。更关键的是，当 instruction 和 context 一起被压缩时，模型常常无法正确遵循指令——这个"instruction confusion"问题在先前工作中未被充分重视。

核心想法

提出 Recurrent Context Compression (RCC)，一种基于 encoder-decoder 的压缩架构：(1) 利用每层输出（而非仅最后一层）进行残差连接，极大提升信息保留；(2) 通过循环分段压缩突破 encoder 窗口限制；(3) 提出指令重建方法解决 instruction confusion 问题。

方法细节

RCC 架构

如图所示，RCC 由 encoder 和 decoder 组成，均从预训练 LLM 初始化：

  • Encoder：将长序列按压缩率分段，每段内取压缩率倍数位置的 token 输出向量作为压缩向量。
  • Decoder：接收压缩向量 + 原始 token embedding。每层 encoder 输出经线性映射后与 decoder 对应层做残差连接（区别于 ICAE 仅用最后一层）。
  • 当 encoder/decoder 层数不匹配时，用复制或平均的规则映射。

训练任务

  1. Random Prompt Text Reconstruction：从 encoder 输入中随机取一段作为 prompt，decoder 根据压缩向量和 prompt 重建后续文本：

    \mathcal{L}_{\text{RAE}} = \max_{h, \ldots, p} P(\mathbf{c} \mid h, \ldots, p; \Theta_{LLM})

  2. Text Continuation：decoder 的 prompt 为 encoder 输入的后续段，训练模型的推理能力。

两阶段长文本训练

  1. 第一阶段：短序列（2048 token）全参数训练，让 encoder 充分学习压缩；
  2. 第二阶段：冻结 encoder，在长序列上继续训练 decoder，使其学会从更多压缩向量中推理。

指令重建方法

当 instruction 和 context 一起压缩时，让 decoder 先从压缩向量中重建 instruction，再基于重建的 instruction 生成回答。训练时将 instruction 重复两次以强化重建能力。

关键结果

文本重建

  • RCC 在 32× 压缩率下 BLEU-4 达到 ~0.95，远超 ICAE 在 64× 下的 ~0.1。
  • 使用全层压缩向量 vs 仅最后层：BLEU-4 从 ~0.6 提升到 ~0.82（64×）。

Passkey Retrieval（1M 序列）

模型 32K 128K 256K 512K 1M
RCC-Transformer-FT-32k 99-100 100 100 98-100 100

在 512× 压缩率下，1M 长度 passkey 检索准确率接近 100%。

LongBench 文档 QA

  • RCC-Ins-Human（手动输入指令）：平均 23.15
  • RCC-Ins-Reconstruction（指令重建）：平均 22.61
  • RCC-Ins-Compress（指令也压缩）：平均 19.61

指令重建有效缓解了 instruction confusion 问题。

局限与延伸阅读

  • 指令重建对超长 instruction 效果有限（decoder 窗口约束）。
  • 缺乏长文本指令微调数据是性能瓶颈。
  • 与 ICAE 对比：RCC 的全层残差连接和循环压缩使其在高压缩率下显著优于 ICAE。
  • 与 Infini-attention 对比：RCC 可直接在开源 LLM 上微调，无需从头预训练。
  • 启发了后续的 LCIRC（NAACL 2025），后者用 Perceiver 架构进一步改进了压缩质量和 query-dependent 能力。

In-Context Former: Lightning-fast Compressing Context for Large Language Model

EMNLP 2024 Findings | Wang et al. (USTC)

问题动机

现有上下文压缩方法面临效率和质量的双重困境：

  1. Self-attention 压缩（如 ICAE、AutoCompressor）的时间复杂度为 \mathcal{O}(n^2)，上下文越长越慢；
  2. 纯 cross-attention 方法缺乏 context token 之间的交互，且忽略了位置信息。

核心诉求是：能否实现线性复杂度的高质量上下文压缩？

核心想法

提出 IC-Former (In-Context Former)，一个基于 cross-attention 的轻量压缩器。关键设计：(1) digest token 作为 query、context token 作为 key/value 的 cross-attention，实现 \mathcal{O}(kn) 线性复杂度；(2) 特殊的 attention mask 让 digest token 既能看到所有 context token，也能看到前面的 digest token，弥补 cross-attention 的交互不足；(3) 应用 RoPE 位置编码保留 token 顺序信息。

方法细节

IC-Former 架构

IC-Former 由若干 cross-attention 层和一组可学习的 digest tokens 组成：

Q = W_Q \tilde{\mathbf{e}}(d)^T
K = W_K [\mathbf{e}(w); \tilde{\mathbf{e}}(d)]^T, \quad V = W_V [\mathbf{e}(w); \tilde{\mathbf{e}}(d)]^T

Attention mask 允许 digest token d_i attend to 所有 context token 和前面的 digest token d_1, \dots, d_{i-1}。时间和空间复杂度为 \mathcal{O}(kn + k^2) \sim \mathcal{O}(kn)。

RoPE 位置编码

为保留 context token 的顺序信息，将 digest token 放在 context token 之后：

Q_{\text{RoPE}} = (R_{n+1}\mathbf{q}_1, R_{n+2}\mathbf{q}_2, \dots, R_{n+k}\mathbf{q}_k)
K_{\text{RoPE}} = (R_1\mathbf{k}_1, \dots, R_n\mathbf{k}_n, \dots, R_{n+k}\mathbf{k}_{n+k})

内积中自然体现相对位置关系：(\text{R}_i \mathbf{q})^T (\text{R}_j \mathbf{k}) = \mathbf{q}^T R_{j-i} \mathbf{k}。

Training

两阶段训练，LLM 始终冻结：

Pretraining——自编码重建任务，IC-Former 将 context 压缩为 digest vectors，LLM 据此重建原文：

\mathcal{L}_{\text{AE}} = -\log p(w | \widetilde{d_1}, \dots, \widetilde{d_k}; \Phi)

Instruction Fine-tuning——用 digest vectors + prompt 输入 LLM，训练其正确回答问题：

\mathcal{L}_{\text{FT}} = -\log p(y | \widetilde{d_1}, \dots, \widetilde{d_k}; p_1, \dots, p_l; \Theta; \Phi)

Divide and Conquer

当 context 长度超过压缩限制时，均匀切分为多个 chunk，各自压缩后拼接：

关键结果

  • IC-Former 仅 19M 参数，在 4× 压缩下媲美 ICAE（70M 参数）和 AutoCompressor（7B 参数微调）。
  • 压缩速度比 ICAE 快 68-112×（取决于 context 长度），因为 cross-attention 的 \mathcal{O}(kn) vs self-attention 的 \mathcal{O}(n^2)。
  • 在 NLU 和 NLG 任务上，128 个 digest token 在 4× 压缩率下 PPL 接近无压缩基线。
  • 在 LongBench 上处理超长 context 时表现优于截断基线。

局限与延伸阅读

  • Cross-attention 架构无法让 context token 之间直接交互，依赖 attention mask 和 RoPE 来弥补。
  • Divide-and-conquer 策略中各 chunk 的压缩是独立的，缺乏跨 chunk 信息流动（与 RCC/LCIRC 的循环压缩形成对比）。
  • 与 Gist Tokens（固定少量 gist token）对比：IC-Former 提供更灵活的压缩比选择。
  • 与 500xCompressor 形成对比：后者追求极端压缩率，IC-Former 注重速度与质量平衡。

Concise and Precise Context Compression for Tool-Using Language Models

ACL 2024 Findings | Xu et al. (HIT, Huawei)

问题动机

Tool-using LLM 需要在上下文中读取工具文档（API 描述、参数格式等）来生成正确的 function call。问题在于：

  1. 工具文档很长（每个工具几百 token），多工具场景下轻松超千 token，占据输入窗口并拖慢解码；
  2. 现有 soft compression 方法存在关键信息丢失（工具名/参数名拼错 → 调用直接失败）和无法灵活调节压缩比两大弱点。

工具文档的特点是：描述性文字可以高度压缩，但名称等关键信息必须原样保留。

核心想法

提出两个互补策略：(1) Selective compression——关键信息（工具名、参数名）保留为原始 text token，只压缩描述性内容；(2) Block compression——将文档分块后按固定长度分别压缩，实现可变压缩比。

方法细节

Basic Soft Context Compression

将 token 序列 T 压缩为 L_S 个 soft token：在 T 后附加 summary token 序列 S，经 compressor 得到隐状态：

H = \text{Compressor}(\text{Emb}(T) \| \text{Emb}(S))

压缩结果 C = H[L_T, L_T + L_S)，decoder 用 C 替代 \text{Emb}(T) 进行生成：

H' = \text{Decoder}(C \| \text{Emb}(T'))

Selective Compression Strategy

将文档拆分为 key information 子序列（不压缩）和 plain 子序列（压缩），构建交错格式：

C = \|_i C_i, \quad C_i = \begin{cases} \text{Emb}(T_i) & T_i \text{ is key info} \\ \text{Compressed}(T_i) & \text{otherwise} \end{cases}

Block Compression Strategy

将待压缩子序列切分为 N_{\text{chunk}} = \lceil \frac{L_T}{r \times L_S} \rceil 个块，每块压缩为 L_S 个 soft token：

C = \|_i \text{Compressed}(T_i)

这样通过改变块数即可实现任意压缩比 r，且 L_S 固定为较小值（如 2）。

Training Pipeline

从 LLaMA-7B 初始化 compressor 和 decoder（同一模型），经历三阶段：

  1. Pre-training：在 SlimPajama 1B token 上学习 soft token 的使用；
  2. Instruction-tuning：在 ShareGPT 数据上获得指令遵循能力；
  3. Fine-tuning：在下游 tool-using 数据集上适配。

关键结果

在 API-Bank 和 APIBench 两个 tool-using benchmark 上：

方法 API-Bank (4×/8×/12×/16×) APIBench (4×/8×/12×/16×)
No compression 71.47 88.24
Overall comp. 68.1/67.1/64.5/61.7 88.2/88.1/85.2/85.7
Selective comp. 70.2/72.8/69.2/72.5 90.3/89.6/87.8/89.1
  • Selective compression 在高压缩比下几乎无性能损失，甚至超越无压缩基线。
  • Name error 分析显示 selective compression 显著减少工具名/参数名拼写错误。
  • Block compression 相比基础 soft compression（如 AutoCompressor 的 50-token 固定长度）带来 +13pp 提升。
  • 对比 GPT-4 硬文本摘要，soft compression 在压缩比和准确率上都大幅领先（GPT-4 摘要仅实现 ~1.4× 压缩）。

局限与延伸阅读

  • Selective compression 依赖人工先验定义"关键信息"（本文为工具名和参数名），泛化到其他领域需要重新定义。
  • Soft compression 需要预训练，计算成本较高，不适用于黑盒模型。
  • 与 LLMLingua 系列（hard token pruning）互补：本文走 soft compression 路线，优势在于高压缩比下信息保留更好。
  • 与 ICAE（reconstruction loss）形成对比：加 reconstruction loss 反而伤害 tool-using 性能，因为模型难以自发意识到名称的重要性。

CoCom: Context Compression for Efficient Answer Generation in RAG

arXiv 2024 · Yeonseok Jeong, Jinmyeong An, Jinheon Baek, Sung Ju Hwang (KAIST)

问题动机

RAG 系统中，将完整检索文档拼接到 prompt 中导致两大问题：（1）长上下文带来的 推理延迟——每生成一个 token 都要 attend 到所有 context token；（2）无关或冗余信息导致的 性能下降（"lost in the middle" 现象）。现有压缩方法要么仅做 extractive 摘要（如 LongLLMLingua），要么压缩率不够极致。

核心想法

训练一个 context encoder 将每篇检索文档压缩为少量 context embedding（1-4 个向量），然后将这些 embedding 直接输入 LLM decoder 代替原始文本。通过三种 decoding 策略（replace / prepend / integrate）探索 embedding 与 LLM 最佳的交互方式。

方法细节

Context Encoder

给定一篇文档 d，用预训练 encoder（如 BERT、Sentence-BERT）编码后，通过可训练的 cross-attention pooling 将文档的 token-level 表示压缩为 n_c 个 context embedding：

\mathbf{z}_1, \ldots, \mathbf{z}_{n_c} = \text{CrossAttn}(\mathbf{Q}_{\text{learnable}}, \text{Encoder}(d))

其中 \mathbf{Q}_{\text{learnable}} 是 n_c 个可学习的 query 向量。

多文档处理

对 k 篇检索文档分别压缩，拼接所有 context embedding：

\mathbf{Z} = [\mathbf{z}_1^{(1)}, \ldots, \mathbf{z}_{n_c}^{(1)}, \ldots, \mathbf{z}_1^{(k)}, \ldots, \mathbf{z}_{n_c}^{(k)}]

k 篇文档总共只需 k \times n_c 个 token（通常 n_c \in \{1,2,4\}）。

三种 Decoding 策略

  1. CoCom-replace：直接将 context embedding 替换原文，prompt 变为 [\mathbf{Z}; q]
  2. CoCom-prepend：在 question 前拼接 context embedding，[\mathbf{Z}; q]，但保留 question 的完整 text attention
  3. CoCom-integrate：在 LLM decoder 的每一层通过 cross-attention 整合 context embedding——类似 Flamingo 的 gated cross-attention

训练

端到端训练 context encoder 和 LLM decoder（可选 LoRA），损失为标准的 answer generation loss：

\mathcal{L} = -\sum_{t=1}^{|a|} \log P(a_t \mid \mathbf{Z}, q, a_{<t})

关键结果

  • 基于 FLAN-T5-base/large 和 Llama-2-7B，在 NQ、TriviaQA、HotpotQA 上评测
  • CoCom（4 embeddings/doc × 5 docs = 20 token）与使用完整 100 tokens/doc 的基线性能相当：NQ EM 46.9 vs 47.2
  • CoCom（1 embedding/doc）在 5x 文档数量 的压缩下仍能保持 90%+ 的性能

500xCompressor: Generalized Prompt Compression for Large Language Models

ACL 2025 · Zongqian Li, Yinhong Liu, Yixuan Su, Nigel Collier (University of Cambridge)

问题动机

LLM 处理长上下文时面临巨大的推理开销——每个 output token 都要 attend 到所有 context token。ICAE 等方法虽然引入了上下文压缩，但压缩率仅约 4x，难以应对千级别 token 的长文档。更关键的是，现有方法需要同时部署 encoder 和 decoder 两套参数，且压缩后的 soft token 无法迁移到其他模型。

核心想法

使用 KV 值（而非 embedding）来传递压缩信息，在 decoder 端完全不引入额外参数，实现高达 500x 的极端压缩率。核心洞察：KV 值比单纯的 embedding 能封装更多信息量，且不增加推理时间。

方法细节

架构

  • Encoder：冻结 LLM \Theta_{\text{LLM}} + 可训练 LoRA 参数 \Theta_{\text{LoRA}}
  • Decoder：原始冻结 LLM \Theta_{\text{LLM}}（无任何额外参数）

Encoder 接收原始文本 token \mathbf{T} = (t_1, \ldots, t_l) 和 k 个 compressed token \mathbf{C} = (c_1, \ldots, c_k)，通过 attention 将文本信息编码到 compressed token 的 KV 值 \mathbf{H_C} 中，传递给 decoder。

预训练（Text Regeneration）

以 \textbf{[BOS]} 触发 decoder 从 KV 值重建原文：

\mathcal{L}_{\text{P}} = -\sum_{i=1}^{l} \log P(t_i \mid \mathbf{H_C}, \textbf{[BOS]}, t_{1:i-1}; \Theta_{\text{LLM}}, \Theta_{\text{LoRA}})

指令微调（Question Answering）

提供问题 \mathbf{Q} 和答案 \mathbf{A}，训练 decoder 从 KV 值中检索信息并生成答案：

\mathcal{L}_{\text{F}} = -\sum_{j=1}^{n} \log P(a_j \mid \mathbf{H_C}, q_{1:m}, a_{1:j-1}; \Theta_{\text{LLM}}, \Theta_{\text{LoRA}})

关键结果

  • 基于 LLaMA-2-7B，在 6x 压缩时 text regeneration 的 ROUGE-L 达到 0.88，即使在 480x 压缩时仍有 0.052 ROUGE-L
  • 在 ArxivQA 上，6x 压缩时 F1 达 88.4%，接近无压缩上限（90.7%）；48x 压缩时仍有 70.2% F1
  • 在经典 QA benchmark（SQuAD、HotpotQA、RACE）上，微调后 6x 压缩性能接近 gold standard
  • 压缩率与信息损失之间呈 幂律关系：初始压缩代价最小，随后边际信息损失递增

局限与延伸阅读

  • 极端压缩（>100x）仍然不可避免地丢失细节信息，尤其是命名实体等低频信息
  • 压缩后的 KV 值依赖于特定 LLM 架构，无法直接迁移到其他模型
  • Decoder 无额外参数的设计保证了无数据泄漏（decoder 本身不存储任何压缩信息），但也限制了 decoder 的适配能力
  • 与 ICAE 同属 autoencoding 路线，区别在于传递 KV 值（而非 embedding）和更激进的压缩目标

LCIRC: A Recurrent Compression Approach for Efficient Long-form Context and Query Dependent Modeling in LLMs

NAACL 2025 | An et al. (Korea University, Google)

问题动机

LLM 受限于固定长度的位置编码，无法高效处理超长输入。核心困难有二：

  1. 位置编码限制：预训练模型只学到 M 个位置 embedding，输入超过 M 后无法处理；
  2. 二次计算复杂度：Transformer 的注意力机制使得长序列计算成本呈平方增长。

现有压缩方法（如 ICAE、AutoCompressor）要么需要重训整个模型，要么在任务相关压缩上表现不佳。特别是，大多数方法是 query-agnostic 的——它们压缩所有信息而不考虑 query 需要什么。

核心想法

提出 LCIRC (Long-form Context Injection with Recurrent Compression)，通过 Perceiver 架构实现循环压缩，并进一步引入 query dependent 压缩（QD-LCIRC），让压缩过程根据用户查询有选择地保留相关信息。仅训练新增组件，保持预训练 LLM 冻结。

方法细节

Recurrent Context Compression

输入序列 x_{1:N} 中超出窗口的部分 x_C = x_{1:N-M} 被分割为 S 个段 \mathbf{s}_1, \dots, \mathbf{s}_S。使用 Perceiver 架构（cross-attention + MLP）进行循环压缩：

\mathbf{h}^{(i)} = \text{Perceiver}(\mathbf{h}^{(i-1)}, \mathbf{s}_i)

其中 \mathbf{h}^{(0)} 为可学习的 query 向量（长度 K \ll N-M）。每个 \mathbf{h}^{(i)} 不仅压缩当前段，还通过循环机制包含所有历史段的信息。最终将所有段的压缩结果拼接：

\mathbf{h} = [\mathbf{h}^{(1)}, \dots, \mathbf{h}^{(S)}]

Compressed Context Injection

通过 Gated Cross Attention Block (GCA Block) 将压缩表示注入冻结的 Transformer 每一层：

\dot{\mathbf{e}}^{(l)}_I = \alpha^{(l)} \cdot \text{CA}(\mathbf{e}^{(l)}_I, \mathbf{h}) + \mathbf{e}^{(l)}_I
\alpha^{(l)} = \tanh(a^{(l)})

其中 a^{(l)} 初始化为 0，保证训练初期不破坏预训练能力。

Query Dependent Compression (QD-LCIRC)

在循环压缩中加入额外的 GCA Block，将用户 query embedding \mathbf{e}_{\text{query}} 注入压缩过程：

\ddot{\mathbf{h}}^{(i-1)} = \text{GCA}(\mathbf{h}^{(i-1)}, \mathbf{e}_{\text{query}})
\mathbf{h}^{(i)} = \text{Perceiver}(\ddot{\mathbf{h}}^{(i-1)}, \mathbf{s}_i)

这使得压缩过程有选择地关注 query 相关的信息。

Random Selective BPTT

训练时空间复杂度随输入长度线性增长。为此提出 Random Selective BPTT：

  • 不同于 Vanilla BPTT（全梯度，不可行）和 Truncated BPTT（仅最后 T 步）；
  • 随机选择若干时间步传递梯度，使模型能高效学习长程 query-dependent 能力。

Training

仅训练新增组件（Perceiver、GCA Block），NLL loss：

\mathcal{L} = -\frac{1}{N} \sum_{i=1}^{N} \log P(x_i | x_{1:i-1})

QD-LCIRC 加入 query 条件：

\mathcal{L} = -\frac{1}{N} \sum_{i=1}^{N} \log P(x_i | x_{1:i-1}, x_{\text{query}})

关键结果

  • 在 InfiniteBench（128K+ 长文本）上，QD-LCIRC 基于 Llama-3.1-8B 在多个任务上超越全量微调的长上下文模型。
  • 在 LongBench 上，LCIRC 在处理超窗口输入时显著优于截断基线。
  • QD-LCIRC 的 query dependent 压缩在 QA 类任务上带来额外提升。
  • 推理效率：当输出长度超过窗口时，模型可迭代压缩已生成 token，持续生成。

局限与延伸阅读

  • Query dependent 训练和评估仅限于 QA 任务，对 IR、对话等场景的泛化待探索。
  • 引入 cross-attention 层增加了训练成本和数据需求。
  • 仅在英文数据集上评估，跨语言能力未知。
  • 延续了 RCC（本主题另一篇）的循环压缩思路，但用 Perceiver 取代了简单的 positional subsampling，并增加了 query-dependent 能力。
  • 与 Infini-attention 互补：LCIRC 可应用于现有 LLM 而无需修改基础架构。

PCRL: Discrete Prompt Compression with Reinforcement Learning

IEEE Access 2024 | Jung & Kim (GIST)

问题动机

Prompt compression 主流方法是 soft prompt（将 prompt 压缩为 embedding），但存在多个实际问题：

  1. 不可解释：soft token 是连续向量，人类无法理解；
  2. 固定长度：需要预设压缩后 token 数，无法自适应调整；
  3. 不可跨模型迁移：embedding 空间与具体 LLM 绑定；
  4. 黑盒不可用：需要 LLM 的 gradient access，无法用于 API 服务。

一个自然的想法是做 discrete prompt compression（保留原始 vocabulary 中的 token），但此前几乎没有系统的工作。

核心想法

提出 PCRL (Prompt Compression with Reinforcement Learning)，将 discrete prompt compression 建模为 RL 问题：policy network 为每个 token 输出 include/exclude 的概率，通过比较压缩前后 LLM 输出的相似度作为 reward 来训练，不需要 LLM 的梯度或标注数据。

方法细节

问题形式化

给定 prompt p = \{x_1, \dots, x_n\}，目标是找到 policy \pi 使得：

\pi^* = \arg\min_{\pi} [\delta(P_{\text{LM}}(y|p), P_{\text{LM}}(y|p^\pi)) + \beta(|p^\pi| / |p|)]

其中 \delta 衡量输出分布偏离，\beta 平衡 faithfulness 和压缩率。

Policy Network

  • 使用冻结的 DistilRoBERTa 提取 token embedding；
  • 附加轻量 MLP 层进行二分类（include/exclude）；
  • Action mask 保护 statement token（如 "Instruction:", "Input:"）不被删除。

RL Training

使用 REINFORCE + Self-Critical Sequence Training (SCST) 算法。MDP 设定为单步决策（contextual bandit）：

  • State：tokenized prompt
  • Action：a = \{a_1, \dots, a_n\} \in \{0,1\}^n，每个 token 的 include/exclude 标签
  • Reward：
R(p, a) = \begin{cases} 1 - |p^\pi| / |p| & \text{if } R_f \geq \tau \\ -\lambda & \text{else} \end{cases}

其中 R_f = \text{ROUGE-L}(LM(p), LM(p^\pi)) 衡量 faithfulness，\tau 为阈值。

Loss function with entropy regularization：

\mathcal{L}(\theta) = (R(p, a) - R(p, \hat{a})) \log \pi_\theta(a|p) + \alpha \mathcal{H}(\pi(\cdot|p))

Token Importance Analysis

分析发现被删除率最高的 token 主要是三类：

  • Stop words：a, the, of, me
  • Punctuation：., .,
  • 词尾：-ribe (Describe), -ify (Identify), -ize (Summarize)

而几乎不被删除的包括：Create, Explain, What, Given, sentence, numbers 等关键语义词。

关键结果

  • 在 Alpaca+ 数据集的 Seen/Unseen/Human 三个验证集上，PCRL 在 ~24.6% 压缩率下保持接近原始 prompt 的性能。
  • GPT2-XL：ROUGE-L 保留率 93.6%（Seen），ChatGPT 评估 win rate 47.3%（接近 50% 上限）。
  • FLAN-T5-XL：ROUGE-L 保留率 92.9%，ChatGPT win rate 45.0%。
  • 显著优于 Selective Context 和 Stop Words Removal 等基线。

跨模型迁移

目标模型 ChatGPT Win% (GPT2-XL policy)
Falcon-instruct (7B) 43.7
LLaMA2-chat (7B) 47.3
FLAN-T5-XXL (11B) 44.8
GPT-3.5-Turbo 49.8

在小模型上学到的压缩策略可以成功迁移到 7B-11B 模型甚至 GPT-3.5，这是 discrete prompt 的独特优势。

局限与延伸阅读

  • Extractive 方法无法进行句子改写，压缩率受限（~25%）。
  • ROUGE 作为 faithfulness metric 在开放式任务上有局限（如两个合理但用词不同的回答会得低分）。
  • 压缩后的 prompt 可能不连贯，但研究表明 LLM 对此有较好的鲁棒性。
  • 与 Selective Context 互补：PCRL 通过 RL 学习 context-dependent 的删除策略，而 Selective Context 基于固定的 self-information 阈值。
  • 启发了后续的 TACO-RL（ACL 2025），后者引入 task-specific reward 并在更大规模模型上验证。

RLPF: Reinforcement Learning from Prediction Feedback for User Summarization with LLMs

AAAI 2025 | Wu et al. (Google DeepMind)

问题动机

用户摘要（User Summarization）是将用户的历史行为序列（如观影记录、搜索历史）压缩为简短的自然语言描述，供下游任务使用。核心挑战：

  1. 无参考摘要：不存在"标准答案"式的用户摘要，无法直接用 supervised fine-tuning；
  2. 评估困难：摘要质量依赖下游任务表现，而非传统的 ROUGE 等文本指标；
  3. 摘要-任务对齐：zero-shot LLM 生成的摘要可能遗漏对下游预测至关重要的信息。

核心想法

提出 RLPF (Reinforcement Learning from Prediction Feedback)：利用 LLM 基于摘要进行下游预测的准确率作为 reward 信号，通过 REINFORCE 算法微调摘要生成模型。不需要参考摘要、不需要人工标注、不需要训练 reward model——直接利用 frozen LLM 的预测能力作为反馈。

方法细节

Problem Formulation

对每个用户 u_i，将其 N 次交互 \{v_i^1, \dots, v_i^N\} 拼接为 user context u_i。Summarizer \pi_\theta 生成摘要 s_i = \pi_\theta(u_i)，frozen LLM 基于摘要做预测 \hat{y}_i = \mathcal{P}(s_i)。

RL Framework (CMDP)

  • State：用户上下文 u_i
  • Action：生成的用户摘要 s_i
  • Policy：summarizer model \pi_\theta
  • Reward：prediction feedback + length penalty
r(s_i) = r^{\text{pred}}(s_i, y_i) + w \cdot r^{\text{len}}(s_i)

Prediction Feedback Reward

用第 N+1 次交互 v_i^{N+1} 作为 ground truth，frozen LLM 基于摘要预测下一次活动：

r^{\text{pred}}(s_i, y_i) = \mathbb{1}(\mathcal{P}(s_i) = y_i), \quad y_i = v_i^{N+1}

为降低零样本预测难度，采用多选题格式（4 个选项包含正确答案）。

Length Reward

控制摘要简洁性：

r^{\text{len}}(s_i) = \min[\mathcal{C}, \beta \cdot (\mathcal{L} - l_i)]

其中 l_i 为摘要 token 长度，\mathcal{L} 为目标长度。

Training

使用 REINFORCE with baseline + KL divergence 约束：

\theta \leftarrow \theta + [(1 - \alpha) \nabla_\theta \mathbb{E}[r_i] - \alpha \mathbb{E}[\nabla_\theta \text{KL}(\pi_\theta \| \pi_{\text{init}})]]

KL 项防止 reward hacking，保持 LLM 原有摘要能力。

关键结果

在 MovieLens-1M 和 Amazon Review 两个数据集上，以 Future Activity Prediction 为 reward 任务训练：

  • RLPF 相比 zero-shot 和 few-shot 基线，下游预测准确率提升 22-38%。
  • 在 未见过的下游任务上也有显著提升，展示了泛化能力：
    • 用"预测下一部电影"训练，在"预测评分"和"推荐解释"上同样有效。
  • 摘要长度在 RL 训练后更加精炼（从 ~380 token 降到 ~200 token），同时质量更高。

关键优势：

  • 单步 RL 训练：无需 RLHF 的三步流程（SFT → reward model → PPO），直接从 frozen LLM 获取 prediction feedback。
  • 对 prompt 变化鲁棒：RLPF 训练后的模型对不同 prompt template 表现稳定。
  • 可扩展到多任务 reward：可同时使用多个预测任务作为 reward 信号。

局限与延伸阅读

  • 目前验证于推荐系统领域的用户摘要，对其他类型文档摘要的适用性待探索。
  • Prediction feedback 的质量依赖 frozen LLM 的零样本预测能力。
  • 多选题格式可能引入 position bias。
  • 与 TACO-RL 的 RL 思路相似，但目标不同：TACO-RL 做 prompt compression（硬删除 token），RLPF 做 abstractive summarization（生成新文本）。
  • 为 agent context management 提供启示：agent 的 trajectory 摘要可以用类似的 prediction feedback 来训练。

TACO-RL: Task Aware Prompt Compression Optimization with Reinforcement Learning

ACL 2025 Findings | Shandilya et al. (Microsoft)

问题动机

LLM 的 prompt 越来越长，推理成本高昂。现有 prompt compression 方法存在两大问题：

  1. 依赖次优指标：如 LLMLingua 系列基于 information entropy / perplexity 来决定删除哪些 token，但这些指标与下游任务目标不对齐；
  2. Task-agnostic：如 LLMLingua-2 将压缩建模为通用 token 分类问题，无法捕获任务特定的信息需求。

不同任务（摘要、QA、代码）对"什么信息重要"的定义截然不同，需要 task-aware 的压缩策略。

核心想法

提出 TACO-RL，在已有的 Transformer encoder token 分类模型（如 LLMLingua-2）基础上，用 task-specific reward signal 通过 REINFORCE 算法进行微调。既利用了 encoder 模型的低延迟优势，又通过 RL 注入了任务感知能力。

方法细节

Encoder Model and Action Sampling

给定 prompt \mathbf{x} = (x_1, \dots, x_n)，encoder policy 输出每个 token 的保留概率 p_i = P(a_i = 1 | x_i)，通过 Bernoulli 采样决定保留/删除：

a_i \sim \text{Bernoulli}(p_i), \quad \forall i \in \{1, \dots, n\}

Task-specific Reward

使用 GPT-3.5-Turbo 分别对原始和压缩 prompt 生成输出 y_{\text{orig}} 和 y_{\text{comp}}，根据任务类型计算 reward：

r = \begin{cases} \mathcal{M}(y_{\text{comp}}, y_{\text{orig}}) & \text{if } -L \leq \delta < L \\ r_0 & \text{otherwise} \end{cases}

其中 \delta = |x_c| - c \cdot |x| 是实际压缩量与目标的偏差，L 为容忍阈值。

Task-specific metrics \mathcal{M}：

  • Summarization：\mathcal{M}_{\text{Sum}} = \text{BLEU}(y_{\text{comp}}, y_{\text{orig}})
  • QA：\mathcal{M}_{\text{QA}} = \text{F1}(y_{\text{comp}}, y_{\text{orig}})

两个关键超参数：

  • Compression Flexibility Controller c：控制目标保留 token 比例，训练时使用，推理时取 top-k 概率 token 满足精确压缩率；
  • Tolerance Threshold L：允许实际压缩量在 [-L, L] 范围内波动，超出则给负 reward r_0。

Policy Optimization

REINFORCE with entropy regularization：

\mathcal{L} = -r \sum_{i=1}^n \log p(a_i | x_i) - \lambda H(\mathbf{p})

梯度更新：

\nabla_\theta \mathcal{L} = -\mathbb{E}_{a \sim p(\cdot|x;\theta)}[r \nabla_\theta \log p(a_i | x_i; \theta)] - \lambda \nabla_\theta H(\mathbf{p})

关键结果

TACO-RL 在三个任务上对比 LLMLingua-2 等 SOTA 基线（相同压缩率和延迟要求下）：

  • Text Summarization (MeetingBank)：性能提升 45%
  • Question Answering (SQuAD)：性能提升 63%
  • Code Summarization (CodeSearchNet)：性能提升高达 189%

关键发现：

  • 单次训练的模型在推理时可泛化到不同压缩率（最高 6×），无需重新训练；
  • BLEU 作为 summarization reward 比 ROUGE 更稳定（因为 ROUGE 是 recall-based，容易被 reward hacking）；
  • 对于 QA 任务，F1 score 作为 reward 最有效。

局限与延伸阅读

  • RL 微调过程需要调用 GPT-3.5 计算 reward，训练成本较高。
  • Reward 函数选择和 base model 质量对结果影响大。
  • 在复杂任务（如从 code summarization 迁移到 code completion）上，RL 带来的提升会减弱。
  • 与 PCRL（IEEE Access 2024）的关系：PCRL 是首个 RL-based discrete compression 工作，但使用 task-agnostic 的 ROUGE-L reward；TACO-RL 扩展了 task-specific reward 设计，并在更强的 base model（LLMLingua-2 encoder）上验证。

Task-agnostic Prompt Compression with Context-aware Sentence Embedding and Reward-guided Task Descriptor

arXiv 2025 | Liskavets et al. (Alterra AI, Queen's University, Workday)

问题动机

主流 prompt compression 方法（如 CPC）依赖显式 question 来引导压缩——计算 question 与每个句子的相关性来决定保留/删除。但实际场景中：

  1. 很多任务没有显式 question（如 summarization、code completion）；
  2. 需要为不同任务手工设计 prompt template，限制了泛化性；
  3. 现有 question-agnostic 方法（如 LLMLingua）性能远不及 question-aware 方法。

核心矛盾：如何在不依赖 question 的前提下实现高质量的 prompt compression？

核心想法

提出 TPC (Task-agnostic Prompt Compression)，通过两个核心模块消除对显式 question 的依赖：

  1. Context-relevant Task Descriptor (CTD)：一个轻量 causal LM，从输入 prompt 自动生成"task description"（替代显式 question），并通过 RL fine-tuning 优化生成质量；
  2. Context-aware Sentence Encoder (CSE)：计算 task description 与每个句子的相关性，用于筛选保留的句子。

方法细节

整体流程

\mathcal{S} = \phi(\hat{q}, c) = \text{TopK}(\{\mathcal{R}(\mathbf{e}_{\hat{q}}, \mathbf{e}_{s_i}) \mid s_i \in c\})

其中 \hat{q} = f_q(p; \theta_q) 是 CTD 生成的 task description，\mathcal{R} 为余弦相似度。

Context-relevant Task Descriptor (CTD)

数据构造：用预训练 LLM 从长文本生成 (prompt, question) pairs，再进一步改写为结构化模板。

Supervised Training：

\mathcal{L} = -\mathbb{E}_{(p,q) \sim \mathcal{D}_{\text{CTD}}} \left[\sum_{t=1}^T \log P(q_t | q_{<t}, p; \theta_q)\right]

Reward-guided Refinement：RL 微调确保生成的 task description 能产生高质量压缩 prompt。Reward 定义为压缩前后 LLM 输出分布的 KL divergence：

R(q_i) = -\text{KL}(P(r | \mathcal{S}) \| P(r | p))

其中 r 为 LLM 用完整 prompt 生成的回答，\mathcal{S} 为压缩 prompt。

\mathcal{L}_{\text{RL}} = -\left[\sum_{t=1}^T \log P(q_{j,t} | q_{j,<t}, p; \theta_q)\right]

q_j 为多个候选 task description 中 reward 最大的。

Context-aware Sentence Encoder (CSE)

训练数据：构造 Multi-hop Context-Question Relevant (MCQR) 数据集，生成需要多步推理的 question，确保 positive sentence 不独立包含完整答案。

引入特殊 token：<end_of_sent> 标记句子边界，<end_of_question> 标记 question 结尾，增强句子级表示学习。

  • 在某些任务（如 Code）上，prompt-agnostic 模式仍显著弱于 prompt-aware 模式。
  • 与 CPC（句子级 prompt-aware 压缩）的关系：TPC 是 CPC 的 task-agnostic 升级版，核心改进是 CTD 模块和 MCQR 数据集。
  • 与 TACO-RL 的 RL 方法不同：TACO-RL 用 RL 微调 compression model 本身，TPC 用 RL 微调 task description generator。

MemAgent: Reshaping Long-Context LLM with Multi-Conv RL-based Memory Agent

问题动机

处理超长文本（书级别、百万 token 级别）是 LLM 的核心瓶颈。现有三类方法各有局限：

  1. 长度外推 + 持续预训练：通过位置编码外推扩展 context window，但在极长文本上性能退化严重，且 O(n^2) 复杂度不变
  2. 稀疏/线性注意力：降低注意力复杂度，但需要从头训练，且存在并行训练困难等问题
  3. 上下文压缩：token 级或外部 memory 模块，但外推能力差，额外模块破坏标准生成流程

理想的长文本处理需要同时满足三个条件：(1) 处理无限长度 (2) 无性能损失地 scale (3) 线性复杂度解码。这三者构成一个 "long-context trilemma"。

核心想法

模仿人类阅读长文档的方式——不试图记住每个细节，而是边读边做笔记，有选择地记录关键信息、丢弃冗余内容。MemAgent 将文档切分为多个 chunk，用一个固定长度的 memory（普通 token 序列）来累积关键信息，每读完一个 chunk 就用 overwrite 策略更新 memory。因为 memory 长度固定，处理每个 chunk 的计算量恒定，总复杂度为 O(N)。

方法细节

Agent Workflow

MemAgent 推理过程分为两个模块：

  1. Context-Processing 模块：逐块迭代读取文档，每次看到新 chunk 后用 overwrite 策略更新 memory。模型在每步只看到 (当前 chunk, 上一轮 memory)，窗口大小恒定。
  2. Answer-Generation 模块：流结束后，模型仅根据问题和最终 memory 生成答案。

自回归建模视角

将 memory 建模为隐变量，原始似然被分解为：

p(\mathbf{x}_{1:N}) = \sum_{\mathbf{m}^{1:K-1}} \prod_{k=1}^{K} \underbrace{p(\mathbf{c}^k \mid \mathbf{m}^{k-1})}_{\text{read}} \cdot \underbrace{p(\mathbf{m}^k \mid \mathbf{c}^k, \mathbf{m}^{k-1})}_{\text{write}}

其中 \mathbf{c}^k 是第 k 个文档 chunk，\mathbf{m}^k 是第 k 步的 memory（长度固定为 M）。每步计算量为 O(C+M)，总复杂度 O(N)。

关键区别于软压缩方法：MemAgent 的 memory 是token 空间中的自然语言文本，人类可读可编辑。

Multi-Conv DAPO 训练

由于 MemAgent 对单个查询生成多轮上下文独立的对话（每轮是一次 chunk 读取 + memory 更新），不能简单套用标准 GRPO 的 attention mask。

Multi-Conv DAPO 的关键设计：

  • 将每轮独立对话作为独立优化目标
  • 由最终答案计算 outcome reward R_i，用 group 归一化的 advantage 广播到所有对话：
\hat{A}_{i,j,t} = R_i - \text{mean}(\{R_i\}_{i=1}^G)
  • 损失函数扩展为三维 (group, conversation, token) 结构：
\mathcal{J}_{\text{DAPO}}(\theta) = \mathbb{E}\left[\frac{1}{\sum_{i=1}^G \sum_{j=1}^{n_i} |o_{i,j}|} \sum_{i=1}^G \sum_{j=1}^{n_i} \sum_{t=1}^{|o_{i,j}|} \left(\mathcal{C}_{i,j,t} - \beta D_{\text{KL}}(\pi_\theta \| \pi_{\text{ref}})\right)\right]

训练配置

  • 基座模型：Qwen2.5-7B/14B-Instruct
  • 训练时 context window 仅 8K（1024 query + 5000 chunk + 1024 memory + 1024 output）
  • 训练数据：RULER-HotpotQA，32K 文档长度，32768 样本
  • 模型通常需要 5-7 轮对话来处理完整文档

关键结果

MemAgent 的核心亮点是极端外推能力：仅用 8K context 训练在 32K 文档上，却能在 3.5M token 的 QA 任务上保持性能损失 < 5%。

Memory-R1: Enhancing LLM Agents to Manage and Utilize Memories via Reinforcement Learning

问题动机

LLM 本质上是无状态的——其记忆受限于固定长度的 context window，超出窗口的信息即被遗忘。这在多 session 长对话等场景中是致命弱点。现有 memory-augmented LLM 方案（如 MemGPT、Mem0、A-Mem）存在两个核心问题：

  1. Memory 管理基于启发式：用 vanilla LLM + in-context 指令来决定 CRUD 操作，没有任何学习信号与任务正确性挂钩。简单场景都容易出错——比如用户说 "我养了一只狗 Buddy"，后来又说 "我又养了一只狗 Scout"，启发式系统可能误判为矛盾执行 DELETE+ADD
  2. 检索噪声：RAG 检索回太多无关 memory 条目，模型需要在相关和无关内容中推理，性能下降

核心想法

用 RL（PPO/GRPO） 训练两个专门的 agent：Memory Manager 学习何时 ADD/UPDATE/DELETE/NOOP，Answer Agent 学习从检索到的 memory 中筛选相关条目（Memory Distillation）并推理回答。Reward 完全基于最终答案正确性，无需标注中间 memory 操作的 ground truth。仅需 152 个 QA pair 即可训练。

方法细节

整体框架

Memory-R1 分两阶段运行：

Stage 1 — Memory Bank 构建与更新：对每个新对话轮次，Memory Manager 决定对 memory bank 执行什么操作：

(o, m') \sim \pi_\theta(\cdot \mid x, \mathcal{M}_{\text{old}})

其中 x 是新信息，\mathcal{M}_{\text{old}} 是当前 memory bank，o \in \{\text{ADD}, \text{UPDATE}, \text{DELETE}, \text{NOOP}\}。

Stage 2 — 基于 Memory 回答问题：Answer Agent 接收问题 q 和通过 RAG 检索的 60 条候选 memory \mathcal{M}_{\text{ret}}，先执行 Memory Distillation（筛选相关条目），再生成答案：

y \sim \pi_\theta(\cdot \mid q, \mathcal{M}_{\text{ret}})

RL 训练

两个 agent 都用 PPO 或 GRPO 训练。

Memory Manager 的 PPO 目标：

\mathcal{J}(\theta) = \mathbb{E}\left[\min\left(\rho_\theta A, \text{clip}(\rho_\theta, 1-\epsilon, 1+\epsilon) A\right)\right]

其中 \rho_\theta = \frac{\pi_\theta(o, m' \mid x, \mathcal{M}_{\text{old}})}{\pi_{\text{old}}(o, m' \mid x, \mathcal{M}_{\text{old}})}。

GRPO 变体：采样 G 个候选操作，用 group-relative advantage 替代 value function：

A_i = \frac{r_i - \text{mean}(\mathbf{r})}{\text{std}(\mathbf{r})}

Reward 设计：完全基于 outcome——Memory Manager 的操作结果传给 frozen Answer Agent，用回答的 Exact Match 作为 reward：

R_{\text{answer}} = \text{EM}(y_{\text{pred}}, y_{\text{gold}})

训练配置

  • 仅需 152 个 QA pair 训练
  • Memory Manager 和 Answer Agent 分别训练（训练其中一个时另一个冻结）
  • 支持 LLaMA-3.1-8B、Qwen-2.5-7B/14B 等多种 backbone

关键结果

在 LoCoMo benchmark 上，Memory-R1-GRPO（LLaMA-3.1-8B）相比最强 baseline Mem0 取得显著提升：

方法 Overall F1 Overall BLEU-1 Overall Judge
LoCoMo (RAG) 11.41 8.71 13.62
Mem0 30.41 22.22 45.68

  • 相比 Mem0：F1 +48%，BLEU-1 +69%，Judge +37% 相对提升
  • GRPO 整体优于 PPO，尤其在 Multi-Hop 和 Temporal 问题上
  • 跨 benchmark 泛化：在 MSC 和 LongMemEval 上也表现优异

局限：

  • Memory Manager 和 Answer Agent 分别训练，未联合优化
  • 仅在对话 QA 任务上验证，未测试 agent 工具调用等更复杂场景
  • Memory bank 增长无上限，实际部署需要考虑存储和检索效率
  • RL reward 仅基于 Exact Match，对开放域问题可能过于严格

ReSum: Unlocking Long-Horizon Search Intelligence via Context Summarization

问题动机

LLM-based web agent 在处理复杂知识密集型查询时，需要大量搜索、浏览和交叉验证。然而 ReAct 范式将每一轮的 thought、action、observation 全部拼接到历史中，很快就会耗尽 context window。现有解决方案如 MEM1、MemAgent 依赖架构修改（如内部 memory token），破坏了与已有 agent 的兼容性，且需要从头端到端重训。

核心矛盾在于：agent 需要充分探索，但 context 窗口有限。

核心想法

ReSum 是一个 plug-and-play 的范式增强，而非架构改动。它周期性地调用外部摘要工具将交互历史压缩为紧凑的 summary，然后从压缩后的状态继续推理，实现理论上无限的探索。配合 ReSum-GRPO 训练算法，通过 advantage broadcasting 将 trajectory-level reward 传播到所有 segment，解决长 horizon 下的 credit assignment 问题。

方法细节

ReSum 范式

Trajectory 初始化：以用户查询 q 开始，\mathcal{H}_0 = (q)。每轮 t，agent 生成 reasoning + tool call，工具返回 observation，历史更新为：

\mathcal{H}_t = \mathcal{H}_{t-1} \circ (\tau_t, a_t, o_t)

Context Summarization：当触发压缩条件（如接近 token 上限）时，调用摘要工具：

s \sim \pi_{\text{sum}}(\cdot \mid \mathcal{H}_t)

然后将工作历史重置为压缩状态 q' = (q, s)，即 \mathcal{H}_t \leftarrow (q')。

ReSum 采用系统化触发（接近 context 上限时自动触发），而非让 agent 自主决定何时压缩。

ReSumTool-30B：专用摘要模型

通用 LLM 难以从冗长嘈杂的搜索历史中提取关键证据。ReSum 通过三阶段 pipeline 训练了专用摘要工具：

  1. Teacher 选择：选择 GPT-OSS-120B 作为教师模型
  2. 数据合成：在 SailorFog-QA 上记录 ReSum trajectory，收集 9000+ 高质量 (Conversation, Summary) 对
  3. 蒸馏训练：将教师能力蒸馏到 Qwen3-30B-A3B-Thinking，得到 ReSumTool-30B

ReSum-GRPO：范式适配 RL 训练

Trajectory 分段：经历 K 次 summarization 的 trajectory 被自然分为 K+1 个 segment：

\mathcal{H}^{(k)} = (q^{(k-1)}, \tau_{t_{k-1}+1}, a_{t_{k-1}+1}, o_{t_{k-1}+1}, \ldots, \tau_{t_k}, a_{t_k}, o_{t_k})

其中 q^{(0)} = q，q^{(k)} = (q, s^{(k)}) 是第 k 次压缩后的状态。

Advantage Broadcasting：计算 trajectory-level reward R_g \in \{0, 1\}，在 group 内归一化得到 advantage：

\hat{A}_g = \frac{R_g - \text{mean}(\{R_1, \ldots, R_G\})}{\text{std}(\{R_1, \ldots, R_G\})}

然后将其 broadcast 到同一 rollout 的所有 segment：\hat{A}_g^{(i)} = \hat{A}_g。

GRPO 目标函数：

\mathcal{J}_{\text{GRPO}}(\theta) = \mathbb{E}\left[\frac{1}{\sum_{g=1}^G n_g} \sum_{g=1}^G \sum_{i=1}^{n_g} \min\left(r_g^{(i)}(\theta) \hat{A}_g^{(i)}, \text{clip}(r_g^{(i)}(\theta)) \hat{A}_g^{(i)}\right)\right]

关键结果

在 GAIA、BrowseComp、BrowseComp-zh 三个 benchmark 上验证。

Training-free 结果：ReSum 相比 ReAct 平均提升 4.5%。WebSailor-30B + ReSumTool-30B 在 BrowseComp 上达 16.0% Pass@1，超过 Claude-4 (12.2%) 和 Kimi-K2 (14.1%)。

RL 训练结果：ReSum-GRPO 仅用 1K 训练样本，在 BrowseComp-zh 上将 WebSailor-3B 从 8.2% 提升到 20.5%，WebSailor-30B 达 33.3%，超过多个使用 10K+ 样本训练的开源模型。

Training dynamics：ReSum-GRPO 通常获得更高 reward，因为它通过摘要延长了本会被截断的 trajectory，使 agent 能从更多探索中学习。

大 context 场景适用性：即使在 128K context 的强 agent 上，ReSum 仍然一致优于 ReAct，说明复杂搜索任务需要超越当前 context 极限的探索能力。

  • 摘要质量依赖于外部摘要工具，引入额外推理开销

ACON: Optimizing Context Compression for Long-horizon LLM Agents

问题动机

LLM agent 在动态环境中执行多步任务时，上下文会无限增长：工具 API 返回值、交互历史、环境状态等不断累积。这带来两个问题：

  1. 推理成本飙升：Transformer 推理成本随 context 长度增长，长 horizon 任务中变得不可承受
  2. 信息稀释：过长上下文中掺杂大量过时或无关信息，反而干扰模型决策

现有压缩方法要么面向对话系统（无法处理多步状态传递），要么面向单步 QA（压缩后即丢弃），都不适用于需要跨步骤保持结构化信号（因果关系、环境状态、前置条件等）的 long-horizon agentic task。

核心想法

ACON 提出一种无梯度的压缩指南优化方法：不训练模型参数，而是用 contrastive task feedback 在自然语言空间中迭代优化压缩 prompt。对比"有压缩失败 vs 无压缩成功"的 trajectory 对，让 LLM 分析失败原因并更新压缩指南。优化后的压缩器还可蒸馏到更小模型。

方法细节

问题建模

将 agentic task 建模为 POMDP \mathcal{E} = \langle \mathcal{S}, \mathcal{A}, \mathcal{O}, \mathcal{T}, \mathcal{R} \rangle。Agent 在每步 t 根据交互历史 \mathbf{h}_{t-1} 和最新观测 o_t 生成动作：

\mathcal{M}(o_t, \mathbf{h}_{t-1}; \theta, \mathcal{P}_{\text{agent}}) \mapsto a_t

优化目标是最大化 task reward 同时最小化 context cost：

\max_{\psi} \mathbb{E}[\mathcal{R}(s_T(\psi))] - \lambda \cdot \mathbb{E}[C(\mathcal{H}'(\psi))]

双层压缩

ACON 同时压缩两类信息：

History Compression：当历史长度超过阈值 T_{\text{hist}} 时触发：

\mathbf{h}_t' = f(\mathbf{h}_t; \phi, \mathcal{P}_{\text{hist}}) \quad \text{if } |\mathbf{h}_t| > T_{\text{hist}}

Observation Compression：当单次观测长度超过阈值 T_{\text{obs}} 时触发：

o_t' = f(o_t, \mathbf{h}_{t-1}; \phi, \mathcal{P}_{\text{obs}}) \quad \text{if } |o_t| > T_{\text{obs}}

Compression Guideline Optimization

核心创新在于用 contrastive task feedback 优化压缩指南 \mathcal{P}：

  1. 收集对比数据 \mathcal{D}_{\text{cont}}：找到"无压缩成功 but 有压缩失败"的任务
  2. 生成 Feedback：让 optimizer LLM 对比压缩前后 context 分析失败原因
  3. 更新 Guideline：聚合多条 feedback 更新压缩指南
\mathcal{P}^{(1)} = \text{LLM}(\text{Update Instruction}, \mathcal{P}^{(0)}, \|_{i=1}^n \text{Feedback}_i)

两步交替优化：

  • Utility Maximization (UT)：基于对比失败案例优化，确保关键信息不丢失
  • Compression Maximization (CO)：基于成功案例优化，鼓励更激进的压缩

蒸馏

将优化后的大模型 compressor 蒸馏到小模型（如 Qwen3-8B/14B、Phi-4），用 LoRA 微调：

f(\cdot; \phi_T, \mathcal{P}) \xrightarrow{\text{prompt opt}} f(\cdot; \phi_T, \mathcal{P}^*) \xrightarrow{\text{distill}} f(\cdot; \phi_S, \mathcal{P}^*)

关键结果

在 AppWorld、OfficeBench、8-objective QA 三个多步 agent benchmark 上验证（均需 10+ 交互步骤）。

Token 效率：ACON 减少 26-54% peak tokens，同时基本保持任务性能。在 8-objective QA 上甚至超过无压缩基线（因为减少了信息干扰）。

Compressor 蒸馏：蒸馏后的小模型保留 95%+ 教师性能，gpt-4.1-mini 在某些 benchmark 上甚至无需蒸馏即可直接作为轻量 compressor。

小模型 Agent 增强：ACON 对小模型 agent 帮助最大——通过压缩减少长上下文干扰，Qwen3-14B 在 AppWorld 上从 26.8% 提升到 33.9%（+26%），在 QA 上 EM 从 0.158 提升到 0.197（+24.7%）。

局限与延伸阅读

局限：

  • History compression 在有 KV-cache 的场景下可能不降低实际 API 成本（因为 cached input tokens 更便宜）
  • Compressor 模块引入额外推理开销
  • Guideline optimization 需要多次环境 rollout，优化成本高
  • 仅在生产力场景（邮件、文档、搜索）验证，未测试更复杂的推理任务

延伸阅读：

  • SUPO / ReSum：用 RL 端到端训练压缩策略，而非 ACON 的 gradient-free 方法
  • MemGPT（2310.08560）：对话导向的 session-level memory 管理
  • LLMLingua / LLMLingua-2：抽取式硬压缩 baseline
  • OpenHands Condenser：类似的基于 prompting 的 agent context 压缩
  • Memory-R1（2508.19828）：用 RL 训练 agent 的 memory 管理能力

SUPO: Scaling LLM Multi-turn RL with End-to-end Summarization-based Context Management

问题动机

在长 horizon 多轮工具调用任务中，用 RL 训练 LLM agent 面临三个核心瓶颈：

  1. 指令遵循退化：随着上下文变长，LLM 的推理和指令遵循能力显著下降。
  2. Rollout 成本过高：更长上下文意味着更长的 rollout 时间，成为 RL 训练的瓶颈。
  3. 上下文长度硬限制：LLM 的 working context length 从根本上限制了 RL 训练能覆盖的 horizon。

现有的 vanilla multi-turn GRPO 直接在一个 context window 中积累所有交互历史，无法突破固定窗口限制。这构成了一个 scalability barrier——没有显式的上下文管理机制，LLM agent 就无法被有效训练来应对真正的 long-horizon 环境。

核心想法

将 summarization 作为 MDP 决策过程的一部分，周期性地把工具调用历史压缩为 LLM 生成的摘要，使 agent 始终在紧凑的 working context 下工作。关键创新在于摘要策略不是预定义或基于规则的，而是 与任务完成策略端到端联合优化——通过 RL，模型自主学习该保留什么信息、如何抽象、如何丢弃无关细节。

方法细节

Summarization-Augmented MDP

在标准多轮工具调用 MDP \mathcal{M}_{\mathcal{V}} 基础上，SUPO 扩展为 \mathcal{M}_{\mathcal{V}}^{\mathtt{sum}}，引入 summarization threshold L。状态转移规则变为：

s_{t+1} := \begin{cases} (s_t, a_t, o_t) & \text{if } v_{\mathtt{sum}} \nsubseteq s_t \text{ and } |(s_t, a_t, o_t)| < L \\ (s_t, a_t, o_t, v_{\mathtt{sum}}) & \text{if } v_{\mathtt{sum}} \nsubseteq s_t \text{ and } |(s_t, a_t, o_t)| \geq L \\ (s_1, a_t) & \text{if } v_{\mathtt{sum}} \subseteq s_t \end{cases}

直觉上：每一步检查上下文长度，一旦超过阈值 L 就触发 LLM 生成摘要 a_{t+1}，然后将状态压缩为（初始 prompt s_1, 摘要 a_{t+1}），相当于用摘要 "重置" context。

Policy Gradient 分解（Theorem 1）

关键理论贡献是证明了：在 \mathcal{M}_{\mathcal{V}}^{\mathtt{sum}} 下，一个完整 rollout 的 policy gradient 可以被分解为 I+1 个 summarized sub-trajectories 的梯度之和。每个 sub-trajectory 形如：

\underbrace{s_1}_{\text{prompt}}, \underbrace{a_{t_{i-1}}}_{\text{上一轮摘要}}, \underbrace{a_{t_{i-1}+1}, o_{t_{i-1}+1}, \cdots}_{\text{多轮工具调用}}, v_{\mathtt{sum}}, \underbrace{a_{t_i}}_{\text{本轮摘要}}

这使得现有 RL 基础设施（如 VeRL）可以无缝适配——只需把一个 rollout 当作多个独立 trajectory 处理。

SUPO 算法

SUPO 基于 GRPO 风格的 policy gradient，优化目标为：

\mathcal{J}_{\texttt{SUPO}}(\boldsymbol{\theta}) := \mathbb{E}\left[\frac{1}{\sum |a_t^j|} \sum_{j=1}^{G} \sum_{i=1}^{I^j+1} \sum_{t} \min\left\{\rho_{t,\ell}^j \hat{A}^j, \text{Clip}(\rho_{t,\ell}^j) \hat{A}^j\right\} \cdot \mathbf{1}\{T^j \leq H, I^j \leq S\}\right]

其中 advantage 估计采用 rollout group 内的相对 advantage：

\hat{A}^j = \frac{R^j - \text{mean}(\{R^{j'}\}_{j'=1}^G)}{\text{std}(\{R^{j'}\}_{j'=1}^G)}

三个关键设计：

  1. Trajectory Management：将每个 rollout 拆分为 I+1 个 sub-trajectory，每个以初始 prompt + 上轮摘要开头，以本轮摘要结尾，直接复用现有 single-trajectory 训练基础设施。
  2. Overlong Masking：mask 掉在最大步数 H 或最大摘要次数 S 前未能给出最终回答的 rollout。没有这一机制，训练会倾向于抑制长 rollout，导致 summarization 模式崩溃。
  3. Advantage Estimation：在 rollout group（而非 trajectory group）内计算相对 advantage，避免长且成功的 rollout 的 advantage 被稀释。

Effective Context Length

定义 effective context length 为 L_{\text{effect}} = L_{\text{RL}} \times (S+1)。例如，在 CodeGym 中使用 4K working context + 最多 7 次摘要，effective context 达 32K；在 BrowseComp-Plus 中使用 64K working context + 最多 2 次摘要，effective context 达 192K。

关键结果

在两个环境上验证：CodeGym（合成交互式函数调用）和 BrowseComp-Plus（搜索任务）。

  • SUPO 在 CodeGym 上用 8 倍更短的 working context 即超越 GRPO
  • 在 BrowseComp-Plus 上带来 +14% 的绝对提升

Summarization 训练动态：训练过程中 summarization rate 持续上升，条件成功率（触发摘要的 rollout 中的成功比例）也在提高，说明工具调用与摘要能力被有效联合优化。

Test-time Scaling：SUPO 训练的模型在推理时可以扩展到更多摘要轮次（超过训练时的 S），准确率持续提升至 60.0%，展现了 summarization 策略的泛化能力。

  • Summarization 指令仍需手动设计，未自动化
  • 有效上下文长度的扩展倍数受最大摘要次数 S 限制

延伸阅读：

  • ACON（2510.00615）：优化 long-horizon agent 的上下文压缩策略

AgeMem: Agentic Memory — Learning Unified Long-Term and Short-Term Memory Management for LLM Agents

问题动机

现有 LLM agent memory 系统将长期记忆（LTM）和短期记忆（STM）割裂管理，二者独立优化后以 ad hoc 方式拼接，导致三个根本性问题：

  1. 功能异质性协调难：LTM 负责 store/update/delete，STM 负责 retrieve/summarize/filter，二者服务于不同目的却需协同工作
  2. 训练范式不匹配：LTM 训练常用 session-level 信息，STM 训练需注入干扰内容模拟长 horizon；标准 RL 假设连续 trajectory，但 memory 操作产生的经验天然是碎片化的
  3. 部署成本高：许多系统依赖辅助 expert LLM 做 memory 控制，推理开销大

ReSum、SUPO 等方法只解决 STM 压缩/摘要，Mem0、Memory-R1 只处理 LTM CRUD，缺乏统一的端到端框架。

核心想法

AgeMem 将 LTM 和 STM 管理统一为 tool-based actions，直接纳入 agent 的策略中。Agent 自主决定何时、存储什么、检索什么、压缩什么、丢弃什么。通过三阶段渐进式 RL 和 step-wise GRPO 实现端到端优化。

方法细节

统一 Memory 工具接口

AgeMem 定义 6 个 memory 工具：

工具 目标 功能
ADD LTM 向 \mathcal{M}_t 添加新知识
UPDATE LTM 修改 \mathcal{M}_t 中的条目
DELETE LTM 从 \mathcal{M}_t 删除条目
RETRIEVE STM 从 \mathcal{M}_t 检索到 C_t
SUMMARY STM 压缩 C_t 中的片段
FILTER STM 过滤 C_t 中的无关内容

统一 RL 建模

状态 s_t = (C_t, \mathcal{M}_t, \mathcal{T}) 同时包含 STM（context C_t）和 LTM（memory store \mathcal{M}_t）。动作空间混合了语言生成和 memory 操作。优化目标：

\theta^* = \arg\max_\theta \mathbb{E}_{\tau \sim \pi_\theta}[R(\tau)]

其中 R(\tau) = \mathbf{w}^\top \mathbf{R} + P_{\text{penalty}}，综合考虑 task completion、context management 和 memory quality。

三阶段渐进 RL 策略

每个 trajectory 分三个阶段：\tau = (\tau^{(1)}, \tau^{(2)}, \tau^{(3)})

  • Stage 1（LTM 构建）：Agent 在自然对话中识别有用信息并存入 LTM
  • Stage 2（STM 抗干扰）：注入 distractor messages，agent 学习 filter/summarize context（Context C_t 在此阶段重置以防信息泄露）
  • Stage 3（协同推理）：接收正式查询，需要同时从 LTM retrieve 和管理 STM 来生成答案

Step-wise GRPO

Terminal reward 通过 advantage broadcasting 反传到所有阶段的所有步：

A_T^{(k,q)} = \frac{r_T^{(k,q)} - \mu_{G_q}}{\sigma_{G_q} + \epsilon}, \quad A_t^{(k,q)} = A_T^{(k,q)} \quad \forall t

目标函数：

J(\theta) = \frac{1}{|\mathcal{E}|} \sum_{q,k,t} \left[\rho_t^{(k,q)} A_t^{(k,q)} - \beta D_{\text{KL}}^{(k,q)}\right]

复合 Reward 设计

  • R_{\text{task}}：LLM-as-Judge 评估答案正确性
  • R_{\text{context}}：评估 STM 效率——压缩效率、预防性操作、信息保留
  • R_{\text{memory}}：评估 LTM 质量——存储质量、维护操作、语义相关性
  • P_{\text{penalty}}：惩罚 context overflow、超时等

关键结果

在 ALFWorld、SciWorld、PDDL、BabyAI、HotpotQA 五个 benchmark 上验证。仅在 HotpotQA 上训练即可泛化到所有数据集。

Memory Quality：AgeMem 存储的 LTM 质量明显优于所有 baseline（MQ 0.533 vs Mem0 约 0.4），说明 RL 训练出了更精选、更可复用的记忆。

Generative Agents: Interactive Simulacra of Human Behavior

问题动机

如何让 AI agent 产生可信的人类行为？现有 NPC 或对话系统要么依赖脚本，要么缺乏对过去经历的记忆和反思能力。一个真正可信的 agent 需要能够：记住经历并随时间推移合成更高层次的反思、根据当前环境和过去经验动态检索记忆、并将这些记忆用于规划未来行为。

核心想法

提出一个将 LLM 与 memory stream + retrieval + reflection + planning 结合的 agent 架构。25 个 generative agent 生活在一个类 Sims 的沙盒世界中，仅需给定一个 agent "想办一个情人节派对"的初始概念，agent 们就能自主传播邀请、结识新朋友、相约赴会——展现出可信的个体和涌现的社会行为。

方法细节

架构三大组件

1. Memory Stream（记忆流）

Memory stream 是一个完整的经历记录，以自然语言形式存储 agent 所有感知到的事件。每条记忆包含：

  • 自然语言描述
  • 创建时间戳
  • 最近访问时间戳

2. Retrieval（检索）

当 agent 需要做决策时，从 memory stream 中检索相关记忆。检索分数由三个因素加权组合：

\text{score} = \alpha_{\text{recency}} \cdot \text{recency} + \alpha_{\text{importance}} \cdot \text{importance} + \alpha_{\text{relevance}} \cdot \text{relevance}
  • Recency（近因性）：指数衰减函数，越近的记忆权重越高
  • Importance（重要性）：由 LLM 为每条记忆打分（1-10），区分日常琐事和重大事件
  • Relevance（相关性）：用 embedding 余弦相似度衡量记忆与当前情境的语义相关性

3. Reflection（反思）

定期将低层次经历合成为高层次抽象。当 importance 分数累积超过阈值时触发反思。流程：

  1. 基于最近经历确定反思主题（"关于 X 最突出的高层次问题是什么？"）
  2. 检索相关记忆
  3. 用 LLM 将检索到的记忆合成为更高层次的 insight
  4. Insight 作为新记忆条目存入 memory stream，可被后续检索和进一步反思

4. Planning & Reacting

  • Planning：Agent 每天早上生成一天的粗略计划，然后递归细化（先小时级，再 5-15 分钟级）
  • Reacting：在每个时间步，agent 感知周围环境并决定是否反应。对话时检索对话对象的相关记忆来生成回复

沙盒环境

25 个 agent 生活在一个 Smallville 小镇中，有咖啡馆、公园、学校、宿舍等场所。用户可以用自然语言与 agent 对话并影响其行为。

关键结果

可信行为涌现：

  • 从一个 agent "想办情人节派对"开始，信息在两天内自主传播：agent 们互相邀请、约会赴约、协调时间一起出席
  • Agent 能维持一致的人格特质和行为
  • 社交关系网络自发形成和演化

消融实验证明架构三组件（observation, planning, reflection）各自关键贡献于行为可信度：

  • 移除 reflection：agent 行为变得浅薄、缺乏深度
  • 移除 planning：agent 行为变得随机、缺乏目标导向
  • 移除 observation：agent 无法感知环境变化

局限与延伸阅读

局限：

  • Memory stream 无限增长，检索效率会随时间下降
  • 没有遗忘机制——人类会选择性遗忘不重要的信息
  • Reflection 粒度固定（按 importance 累积触发），缺乏适应性
  • 完全基于 prompting，没有学习/优化 memory 管理策略

延伸阅读：

  • MemGPT（2310.08560）：将 OS 虚拟内存思想引入 LLM memory 管理
  • RMM（2503.08026）：Prospective Reflection（前瞻性反思）+ Retrospective Reflection（回顾性反思）的改进版
  • Memory-R1（2508.19828）：用 RL 学习 memory CRUD 操作
  • AgeMem（2601.01885）：统一 LTM/STM 的 RL 框架

Recursively Summarizing Enables Long-Term Dialogue Memory in Large Language Models

问题动机

LLM（如 GPT-4）在长对话中会遗忘过去的信息，产生不一致的回复。例如在 20+ 轮对话中，ChatGPT 会忘记之前讨论过的话题，导致对话质量下降。现有方法存在两类问题：

  1. 检索方法：直接存储历史语句并用检索器查找相关内容，但很难保证检索到的语句捕获完整语义
  2. Memory 方法（如 MemoChat、MemoryBank）：使用 LLM 生成摘要作为 memory，但 memory 一旦生成就固定不变，无法随对话推进而更新，导致信息过时

核心想法

让 LLM 自己递归地生成和更新摘要：先对第一段对话生成初始 memory，然后在每段新对话结束时，将旧 memory 和新对话一起输入 LLM 生成新 memory。最终用最新 memory 辅助 LLM 生成回复。数学上建模为 Markov 过程：P(M_N|S) = \prod_{i=1}^N P(M_i | S_i, M_{i-1})。

方法细节

形式化定义

长上下文对话 D = \{S, C_t, r_t\}，其中 S = \{S_1, S_2, \ldots, S_N\} 是 N 个历史 session。目标分解为两个阶段：

P(r_t | C_t, S) = P(r_t | C_t, M_N) \cdot P(M_N | S)

其中 M_i 是第 i 个 session 结束后的 memory，P(M_N|S) = \prod_{i=1}^N P(M_i | S_i, M_{i-1}) 是 sequential/Markov 过程。

三步流程

  1. Memory 初始化：对第一个 session S_1，prompt LLM 生成初始摘要 M_1
  2. 递归更新：对后续每个 session S_i，将 M_{i-1} 和 S_i 拼接后 prompt LLM 生成更新后的 M_i
  3. 回复生成：用最新 memory M_N 和当前对话上下文 C_t 生成回复 r_t

关键优势

  • Memory 长度远小于完整对话，作为一种潜在的超长文本建模方案
  • 可与 ICL（in-context learning）结合：提供 (对话, memory, 黄金回复) 示例进一步提升
  • 与长 context window（如 GPT-3.5-Turbo-16K）和 RAG 方法正交互补

关键结果

在 Multi-Session Chat 数据集上验证，覆盖多种开源和闭源 LLM。

核心发现：

  • 递归摘要在自动和人工评估中均优于检索方法和非递归 memory 方法
  • 仅用 2-3 个 ICL 示例即可显著提升效果
  • 在 text-davinci-003 上 BLEU 提升约 +3%
  • 互补性：与 GPT-3.5-Turbo-16K（大 context window）和 BM25/DPR（检索增强）组合后效果进一步提升

局限与延伸阅读

局限：

  • 递归摘要累积信息丢失——越靠前的对话信息经过越多次压缩，可能被逐渐淡化
  • 没有选择性机制——所有信息被同等对待，无法区分重要和不重要的内容
  • 仅在对话场景验证，未测试 agent 工具调用等复杂场景
  • Memory 质量完全依赖 LLM 的摘要能力

延伸阅读：

  • MemGPT（2310.08560）：同期工作，也使用递归摘要作为核心机制之一（FIFO Queue 驱逐时生成递归摘要）
  • ReSum（2509.13313）：将周期性摘要与 RL 训练结合用于 web search agent
  • RMM（2503.08026）：用 topic-based 摘要替代 session-based 固定粒度
  • Generative Agents（2304.03442）：记忆流 + 反思机制的经典 agent memory 架构

MemGPT: Towards LLMs as Operating Systems

问题动机

LLM 受限于固定的 context window，在需要处理超长对话或大型文档时严重受限。一旦信息超出窗口，就彻底"遗忘"。现有方法（如简单截断、RAG）要么丢失连续性，要么缺乏系统性的上下文管理机制。

核心想法

借鉴操作系统中虚拟内存的分层管理思想：物理内存有限，但通过在物理内存和磁盘之间分页（paging），可以提供扩展的虚拟地址空间的假象。MemGPT 类比地将 LLM 的 context window 视为"物理内存"，将外部存储视为"磁盘"，通过 virtual context management 在二者之间智能调度信息，使 LLM 在有限 context 下获得"无限记忆"的能力。

方法细节

多级 Memory 架构

Main Context（主内存，即 prompt tokens） 分为三部分：

  • System Instructions（只读）：包含 MemGPT 控制流程、memory 层级说明、function 使用方法
  • Working Context（固定大小读写区）：存储用户偏好、关键事实等核心信息，仅通过 function call 修改
  • FIFO Queue（消息队列）：滚动存储最近消息，队首维护一个递归摘要（recursive summary），记录已被驱逐消息的概要

External Context（外部存储，即 "磁盘"） 包括：

  • Recall Storage：完整的消息数据库，所有消息永久存储，可通过 function call 检索
  • Archival Storage：读写数据库，存储任意长度的文本对象

Queue Manager（队列管理器）

当 prompt tokens 超过 warning token count（如 70% context window）时，向 LLM 发送"memory pressure"警告，让 LLM 有机会将重要信息存入 Working Context 或 Archival Storage。当超过 flush token count（如 100%）时，强制驱逐消息（如 50%），并用驱逐消息 + 现有递归摘要生成新的递归摘要。

Function Executor（函数执行器）

Memory 管理完全由 LLM 自主驱动：通过 function call 决定何时在 context 层级间移动数据。LLM 可以：

  • 将 FIFO 中即将溢出的重要信息写入 Working Context 或 Archival Storage
  • 从 Recall/Archival Storage 检索历史信息回 FIFO Queue
  • 修改 Working Context 以反映对用户的最新理解

Function Chaining

支持多个 function call 串联执行（如翻页浏览检索结果、从不同文档整合信息），通过 yield/non-yield 标志控制是否立即返回给 LLM processor。

Event-Driven Control Flow

Events 触发 LLM 推理：用户消息、系统消息（memory 压力警告）、用户交互（登录、上传文档）、定时事件（允许 MemGPT "无 prompt" 运行）。

关键结果

在两个场景评估：

Document Analysis（文档分析）：MemGPT 能分析远超 LLM context window 的大型文档。在 nested key-value retrieval 任务中，当文档扩展到多页时，MemGPT 的 paging 机制允许遍历多个 archival storage 页面找到答案。

Multi-session Chat（多轮对话）：MemGPT 创建的对话 agent 能记住、反思并动态进化。在 deep memory retrieval 评估（需要回忆早期对话的信息）中，MemGPT 显著优于固定 context 基线。

局限与延伸阅读

局限：

  • 完全依赖 LLM 的 function calling 能力，对小模型可能不适用
  • Memory 管理决策全靠 in-context 指令，没有学习信号（无 RL/SFT）
  • 递归摘要累积误差可能导致信息丢失
  • 控制流复杂，debug 困难

延伸阅读：

  • Memory-R1（2508.19828）：在 MemGPT 思想基础上加入 RL 训练 memory 管理
  • AgeMem（2601.01885）：统一 LTM/STM 管理的 RL 框架
  • Generative Agents（2304.03442）：memory stream + retrieval + reflection 的经典 agent 架构
  • Mem0：生产级 memory 基础设施，类似 MemGPT 的 CRUD 思路

RMM: Reflective Memory Management for Long-term Personalized Dialogue Agents

问题动机

LLM 的无状态特性使其在多 session 长期对话中无法保持个性化。虽然外部 memory 机制已被提出（如 MemGPT、MemoryBank），但现有方法存在两个关键局限：

  1. 固定粒度：按 turn、session 或时间间隔预定义的边界组织 memory，可能不对齐对话的语义结构（如话题切换），导致信息碎片化
  2. 固定检索器：使用不可适应的检索机制，无法针对不同对话领域和用户交互模式进行调整；收集标注数据训练个性化检索器成本极高

核心想法

提出 Reflective Memory Management (RMM)，结合两种反思机制：

  • Prospective Reflection（前瞻反思）：将对话历史分解为 topic-based 记忆表示，跨 turn/session 边界整合碎片信息，为未来检索做优化
  • Retrospective Reflection（回顾反思）：利用 LLM 生成回复时的 citation attribution 信号，通过在线 RL 迭代优化 reranker

方法细节

整体框架

RMM 由四个组件组成：

  • Memory Bank：存储 (topic summary, raw dialogue) 对
  • Retriever：基于 query 检索 Top-K 相关记忆
  • Reranker：轻量级模块，精炼检索结果为 Top-M
  • LLM：生成回复并提供 citation 反馈

算法流程：检索 → Rerank → 生成回复 + citation → RL 更新 reranker → (session 结束时) 提取 topic-based 记忆 → 更新 memory bank。

Prospective Reflection（前瞻反思）

在每个 session 结束后：

  1. Memory Extraction：用 LLM 从对话中提取不同 topic 的 snippet 和对应 summary
  2. Memory Update：对每条提取的记忆，检索 memory bank 中 Top-K 语义相似条目，由 LLM 决定直接添加（新 topic）还是合并（已有 topic 的更新）

这样 memory bank 围绕 topic 组织，而非固定的 turn/session 边界。

Retrospective Reflection（回顾反思）

Reranker 设计：

Embedding 适配 + Gumbel Trick 随机采样：

\mathbf{q}' = \mathbf{q} + \mathbf{W}_q \mathbf{q}, \quad \mathbf{m}_i' = \mathbf{m}_i + \mathbf{W}_m \mathbf{m}_i
\tilde{s}_i = \mathbf{q}'^\top \mathbf{m}_i' + g_i, \quad g_i = -\log(-\log(u_i))

LLM Attribution 作为 Reward：让 LLM 在生成回复时同时生成对每条检索记忆的 citation。被引用的记忆 reward = +1（Useful），未被引用的 = -1（Not Useful）。

Reranker 更新：使用 REINFORCE 算法：

\Delta \phi = \eta \cdot (R - b) \cdot \nabla_\phi \log P(\mathcal{M}_M | q, \mathcal{M}_K; \phi)

这种无监督的在线优化方式不需要标注数据，能随对话推进不断适应。

关键结果

SUMER: Goal-Directed Search Outperforms Goal-Agnostic Memory Compression

问题动机

现有 LLM memory 系统（MemGPT、A-Mem、Mem0 等）都聚焦于一个问题：如何最优地压缩 memory。但这些系统依赖 goal-agnostic 的 CRUD 启发式——在不知道未来会被问什么的情况下决定存储/丢弃什么。这存在根本矛盾：

  1. 压缩是有损的：预定义的压缩算法不可能适配所有数据分布
  2. Human bias 内嵌：更多的工程化 prompt 和 memory 架构只是把人类偏见嵌入系统，而非找到通用解
  3. Bitter Lesson：AI 历史反复证明，search + learning 最终优于手工知识表示（如 AlphaGo）

核心想法

不压缩，而是学习搜索。SUMER（Search in Uncompressed Memory via Experience Replay）直接在未压缩的原始对话数据上保存所有信息，用 RLVR（Reinforcement Learning with Verifiable Rewards）训练 LLM agent 学习使用搜索工具（keyword search + semantic search）来定向查找信息并回答问题。

方法细节

系统架构

SUMER 将每条对话消息原样存入 memory bank，用 Qwen3-Embedding-0.6B 预计算 embedding。Agent 通过两种搜索工具访问 memory：

  • Semantic Search：用 embedding 余弦相似度找 Top-K 语义相似的记忆
  • Keyword Search：返回所有包含指定关键词的记忆

两种搜索都支持按 speaker 和 session 过滤。每条检索到的记忆还附带前后 2 条消息作为上下文。

GRPO 训练

用 GRPO 训练 agent 的搜索策略。对每个问题采样 G=8 条 trajectory，计算 group-normalized advantage：

A_i = \frac{r_i - \mu_r}{\sigma_r + \epsilon}

GRPO 目标函数（无 KL regularization）：

J(\theta) = \mathbb{E}\left[\frac{1}{G}\sum_{i=1}^G \sum_{t=1}^{|o_i|} \min\left(\rho_{i,t} \hat{A}_{i,t}, \text{clip}(\rho_{i,t}) \hat{A}_{i,t}\right)\right]

关键设计：

  • Multi-turn masking：tool responses 作为 context 可见，但不计入 policy loss——只训练 agent 自己的输出
  • Advantage broadcasting：将 rollout-level advantage 广播到 token 级，并用 mask m_{i,t} 屏蔽 prompt 和 tool response

Reward 设计

R = \begin{cases} \mathbb{J}(y_{\text{pred}}, y_{\text{gold}}) \cdot F_1(y_{\text{pred}}, y_{\text{gold}}) & \text{if answer submitted} \\ -1 & \text{if no answer submitted} \end{cases}
  • LLM-as-Judge（gpt-oss-120B）做语义正确性判断
  • Token-level F1 引导输出格式（简洁精确）
  • 超时未提交答案 reward = -1

训练数据极简

仅用 LoCoMo 数据集中 1 个对话（191 个问题）训练，其余 9 个对话作为验证集。

关键结果

  • 未测试需要持久化 world model 或 schema learning 的更复杂任务

Compressive Transformers for Long-Range Sequence Modelling

问题动机

Transformer 模型通过保留所有过去 hidden activation 实现了远超 RNN 的上下文建模能力，但也带来了 存储和计算成本的线性/平方增长。TransformerXL 通过 FIFO memory 保留最近的 activation，但当 memory 满时直接丢弃最旧的 activation。这意味着模型的有效时序范围（temporal range）受到 memory 大小的硬性限制——超出范围的历史信息彻底丢失。

人类记忆并不储存一生中的所有感官体验，而是通过 有损压缩（lossy compression）选择性地保留重要信息。本文的核心问题是：能否让 Transformer 也学会 压缩而非丢弃 过期的 memory？

核心想法

在 TransformerXL 基础上增加一层 compressed memory：当最旧的 memory 被挤出时，不丢弃它们，而是通过一个压缩函数 f_c 将它们映射为更少的向量，存入二级 FIFO 压缩记忆中。模型同时对 fine-grained memory 和 coarse compressed memory 做 attention，以 指数级 扩大有效时序范围，同时保持相同的 attention 计算量。

方法细节

整体架构

模型维护三部分状态：

  • Sequence（当前输入窗口，大小 n_s）
  • Memory（fine-grained FIFO，大小 n_m）
  • Compressed Memory（coarse FIFO，大小 n_{cm}）

每处理完一个 sequence window，hidden activation 被推入 memory；memory 中最旧的 n_s 个 activation 通过压缩函数映射为 \lfloor n_s / c \rfloor 个 compressed memory（c 为压缩率）。

压缩函数

f_c : \mathbb{R}^{n_s \times d} \rightarrow \mathbb{R}^{\lfloor n_s / c \rfloor \times d}

候选方案包括：

  1. Max/Mean pooling（kernel 和 stride 均为 c）
  2. 1D 卷积（kernel 和 stride 均为 c，含可训练参数）
  3. Dilated 卷积
  4. Most-used：按平均 attention 权重排序，保留被访问最多的 memory

压缩损失

由于压缩网络需要训练，直接用 BPTT 从主损失传梯度需要极长的 unroll。作者提出 attention-reconstruction loss——让压缩后的 memory 在 content-based attention 下重建出与原 memory 相同的 attention 输出：

\mathcal{L}^{attn} = \sum_{i=1}^{l} \| \text{attn}(\mathbf{h}^{(i)}, \text{old\_mem}^{(i)}) - \text{attn}(\mathbf{h}^{(i)}, \text{new\_cm}^{(i)}) \|_2

这是一个 有损 压缩目标——不再被 attend 的信息可以被丢弃。实验表明这比 auto-encoding loss 效果更好。

时序范围

TransformerXL 的最大时序范围为 l \times n（l 层，memory 大小 n）。Compressive Transformer 将其扩展为：

l \times (n_m + c \cdot n_{cm})

设 n_{cm} = n_m = n/2，c = 3，则时序范围扩大为 TransformerXL 的 2 倍，而 attention 计算量不变。

基准 指标 TransformerXL Compressive Transformer

WikiText-103 PPL 18.1 17.1 (SOTA)

关键发现：Compressive Transformer 对 低频词 的建模提升最大（约 20%），而高频词提升很小（2.6%）——说明压缩记忆帮助模型更好地利用远程上下文中的稀有信息。

Attention 分析

平均 attention 权重分析揭示了一个关键现象：在 memory → compressed memory 的过渡处，attention 权重出现了 上升。这与"越旧的记忆被访问越少"的直觉相反——模型确实学会了在压缩记忆中保留显著信息。

最优组合是 Conv + Attention-reconstruction loss（0.973 BPC），压缩率 c=3。

  • 额外复杂度：如果任务不需要长程推理，Compressive Transformer 不会带来额外收益。
  • 固定压缩率：所有层使用相同的压缩率 c，未来可以探索逐层自适应压缩。
  • 本文提出的 PG-19 数据集（28,752 本书，11GB 文本，平均 69K 词/本）成为了长程语言建模的标准 benchmark。
  • 与 RMT（将信息压缩到少量 memory token 中）和 Infini-attention（用关联矩阵做增量更新）相比，Compressive Transformer 的压缩发生在 hidden activation 层面，是一种更显式的分层记忆架构。

Memorizing Transformers

问题动机

语言模型通常需要训练或微调才能获取新知识。如果模型能在推理时 直接读取并记忆新数据，就可以即时获取新知识。现有的扩展上下文的方法（如 TransformerXL）通过缓存前一个 segment 的 hidden state 来扩展窗口，但缓存大小有限（通常 512 token），且增大缓存会线性增加计算成本。

能否让模型拥有一个巨大的外部记忆（262K token），通过近似检索高效访问？

核心想法

在 Transformer 的某一层（靠近顶部）添加一个 kNN-augmented attention layer：除了对 local context 做标准 dense attention，还对一个 非参数化的外部 (key, value) 记忆 做近似 kNN 检索。两路 attention 的结果通过 learned gate 融合。记忆不参与梯度计算，仅在推理时不断追加新的 (key, value) 对。

方法细节

架构

模型主体是标准 decoder-only Transformer。长文档按 512 token 切分为 subsequence，顺序送入模型（不 shuffle）。同时维护一个 TransformerXL 风格的 sliding-window cache（512 token）。

kNN-Augmented Attention Layer

在某一层（靠近 stack 顶部），对每个 query token：

  1. Local attention：标准 dense self-attention over 当前 subsequence + XL cache
  2. External memory attention：用同样的 query 在外部记忆中做 approximate kNN search，返回 top-k (key, value) pairs
  3. Gate 融合：
g = \sigma(b_g)
\mathbf{V}_a = \mathbf{V}_m \odot g + \mathbf{V}_c \odot (1 - g)

其中 b_g 是 per-head 的 learned scalar bias。实验发现大多数 head 最终学会几乎完全依赖外部记忆。

每个 training step 结束后，local context 的 (key, value) pairs 被追加到外部记忆尾部。记忆满时，最旧的 pair 被丢弃。

处理分布偏移

由于模型参数在训练过程中不断变化，旧的 key/value 可能变"过期"（stale）。解决方案：

  • Query/Key 归一化：确保新旧 key 在幅度上一致
  • 分阶段训练：先用小记忆（8192）预训练，再 finetune 到大记忆

近似 kNN

使用 approximate kNN（recall ~90%）替代精确搜索，大幅提升速度。可进一步用 Faiss、ScaNN 等库扩展到数十亿级。

Batching

多个不同长度的文档被 pack 到同一个 batch 中，每个文档维护独立的外部记忆，在文档边界处清空。

关键结果

语言建模

在多个 benchmark 上，Memorizing Transformer 一致优于 vanilla Transformer 和 TransformerXL：

数据集 Transformer TransformerXL Memorizing Transformer
C4 18.38 17.81 17.27
PG-19 12.59 11.88 11.37
arXiv 2.72 2.42 2.26
Github 1.37 1.16 1.09
Isabelle 3.21 2.33 2.01

Memory 大小的影响

性能随记忆大小 稳定提升，从 1K 到 262K token 均有持续收益，且未出现饱和趋势。不同数据集的收益差异大：代码和数学论文（局部性强、定义可复用）收益最大。

推理时利用新知识

在 arXiv 数学论文上，模型能在测试时利用 当前文档中新定义的定理和函数——这些定义从未出现在训练数据中。类似地，在 Isabelle 形式化证明中，模型能引用同一文件中先前定义的 lemma。

Fine-tuning 效率

即使是在较小数据集上 fine-tune 一个已训练好的模型加入外部记忆，也能快速获得收益。

局限与延伸阅读

  • 仅在单层使用 kNN attention：在所有层都加外部记忆会使存储成本过高。
  • 记忆不参与训练：外部记忆的 key/value 是 detached 的，没有直接的梯度信号来优化什么该被存储。
  • Distributional shift：训练过程中参数变化导致的 key 过期问题仅通过归一化缓解，未彻底解决。
  • Infini-attention 在相同框架下提出了 参数化 的压缩记忆（associative matrix），相比 Memorizing Transformer 的 262K (key, value) 存储实现了 114× 压缩率，同时性能更优。
  • FINCH 则从 KV cache 压缩的角度切入，选择性保留最相关的 KV pair。

Recurrent Memory Transformer

问题动机

Transformer 的 self-attention 将全局和局部信息存储在同一组 element-wise representation 中，导致全局特征被"稀释"（blurred）。此外，self-attention 的 O(N^2) 复杂度限制了输入长度。TransformerXL 通过缓存前一 segment 的 hidden state 扩展上下文，但缓存本质上是 把 token representation 同时当作存储和计算载体——这种混用在需要跨多个 segment 传递信息时效率低下。

核心想法

在输入序列的首尾添加 专用 memory token，让 Transformer 学会将序列信息写入（write）memory、从 memory 中读取（read），并通过 segment 间的 memory 传递实现 递归。关键优势：不需要修改 Transformer 本体，只改输入和输出序列。

方法细节

架构

对于 decoder-only 模型，m 个 memory token 同时放在 segment 的 开头（read memory）和 结尾（write memory）：

\tilde{H}^{0}_{\tau} = [H_{\tau}^{mem} \circ H_{\tau}^0 \circ H_{\tau}^{mem}]
\bar{H}^N_\tau = \text{Transformer}(\tilde{H}^{0}_{\tau})

输出分为三部分：

[H_{\tau}^{read} \circ H_{\tau}^N \circ H_{\tau}^{write}] := \bar{H}^N_\tau

递归连接

Write memory 的输出传递为下一 segment 的 memory 输入：

H_{\tau+1}^{mem} := H_{\tau}^{write}

这使得 memory 在每个 segment 被 Transformer 所有层处理一次，经过 \tau 个 segment 后，memory 实际经过了 \tau \times N 层变换——远比 TransformerXL 的逐层缓存更"深"。

BPTT 训练

RMT 通过 Backpropagation Through Time 在 segment 之间传递梯度（不 stop gradient），BPTT unroll 深度是超参数。实验发现 更深的 BPTT unroll 显著改善性能。

与 TransformerXL 结合

RMT 可以与 TransformerXL cache 组合使用：cache 作为 短期记忆，RMT memory 作为 长期记忆，在 WikiText-103 上取得了最优结果（PPL 23.99）。

关键结果

算法任务

在 Copy、Reverse 等需要跨 segment 传递信息的算法任务中，当 segment 数量增加时，TransformerXL 性能快速退化到 baseline 水平，而 RMT 保持接近完美的准确率。

语言建模（WikiText-103）

RMT 用 更少的 memory size 达到与 TransformerXL 相当的 perplexity：

  • RMT memory=10 ≈ TransformerXL cache=75（segment=150）
  • RMT memory=1 ≈ TransformerXL cache=10（segment=50）

这说明 RMT 学会了 更高效的信息压缩。

Memory 操作可视化

Attention map 揭示了清晰的 memory 操作模式：

  • (a) 写入：序列 token → write memory（按顺序/逆序）
  • (b) 读取：read memory → 序列输出
  • (c) 保持：read memory → write memory（跨 segment 信息传递）

Pretrained 模型增强

将 RMT 加到预训练的 RoBERTa-base 上做长文本分类（Hyperpartisan），仅 10 个 memory token 就在 4 个 segment（约 2000 token）上达到了 98.11 F1，超越了 Big Bird（4096 token）、Longformer（4096 token）等专用长文本模型。

局限与延伸阅读

  • 训练不稳定：大 memory + 深 BPTT unroll 容易 OOM 或训练不稳定。
  • Memory 容量有限：随着 memory size 增大，边际收益递减——存在一个与任务匹配的最优 memory 大小。
  • RMT 是后续 RMT-1M（将 BERT/GPT-2 扩展到百万 token）的基础。
  • 与 Compressive Transformer（压缩 hidden activation）不同，RMT 使用 显式 memory token 作为信息瓶颈，更接近 Neural Turing Machine 的思路。

Scaling Transformer to 1M Tokens and Beyond with RMT

问题动机

Transformer 的 O(N^2) self-attention 是扩展序列长度的主要瓶颈。现有长上下文方法（Longformer、Big Bird、LongNet）虽然降低了计算复杂度，但 memory 占用仍随输入线性增长，在单 GPU 上最多处理 33K-64K token。没有任何深度神经网络被报告成功处理过百万 token 级别的序列。

核心想法

将 RMT 的 token-based memory 机制应用到 预训练 的 Transformer 模型（BERT、GPT-2）上，通过 segment-level 递归 + curriculum learning，以 线性计算复杂度和常数 memory 处理最高 200 万 token 的序列。

方法细节

预训练模型增强

对 encoder-only 模型（BERT），m 个 memory token 只加在 segment 开头：

\tilde{H}^{0}_{\tau} = [H_{\tau}^{mem} \circ H_{\tau}^0]

对 decoder-only 模型（GPT-2），仍使用 read/write 分离。处理完一个 segment 后，memory 输出传递到下一个：

H_{\tau+1}^{mem} := \bar{H}_{\tau}^{mem}

计算复杂度优势

RMT 将输入分成固定长度的 segment，只在 segment 内计算 full attention，因此 推理 FLOPs 随序列长度线性增长。在 2M token 上，RMT 相比 OPT-175B 减少 29\times FLOPs，相比 OPT-125M 减少 295\times FLOPs。

Curriculum Learning

关键训练策略——逐步增加 segment 数量：

  1. 先在 1 个 segment 上 fine-tune 至收敛
  2. 然后增加到 2 个 segment，以此类推
  3. 在后续阶段混入之前长度的样本，改善泛化

没有 curriculum 的直接训练无法收敛。

合成记忆任务

设计了三个难度递增的任务：

  • Memorize：fact 在序列开头，question 在结尾
  • Detect & Memorize：fact 随机放置在序列中
  • Reasoning：两个 fact 随机放置，需推理回答

Attention Map 分析

Attention map 清晰展示了 RMT 学到的 memory 操作：检测 fact → 写入 memory → 保持 memory → 从 memory 读取回答。

关键结果

百万 token 级别泛化

在仅 7 个 segment（约 3,500 token）上训练后，RMT 增强的 BERT 可以在推理时泛化到 4,096 个 segment（超过 200 万 token）：

  • Detect & Memorize 任务保持接近完美的准确率
  • Reasoning 任务在百万 token 级别仍有 >80% 准确率
  • Memory 占用始终为常数（实验中仅 3.6 GB）

语言建模

RMT 增强的 GPT-2 在 ArXiv 数据集上：

  • 随 segment 数量增加，perplexity 持续改善
  • 训练更多 segment 后，对更长上下文的泛化更好
  • 可以与 LoRA/Adapter 等参数高效方法组合

形式化定理证明

RMT 增强的 GPTNeo-1.3B 在 Lean 形式化证明任务上，相比无 memory 的 baseline 有显著的 perplexity 改善。

局限与延伸阅读

  • Curriculum 依赖：训练策略对泛化能力影响很大，不如普通 Transformer 训练简单。
  • 百万 token 仅在合成任务验证：目前缺少百万级 NLP benchmark 来全面评估。
  • 信息瓶颈：full attention 模型在理论上仍有优势——RMT 的 memory 毕竟是压缩表示，不是原始 hidden state。
  • 与 Infini-attention 和 Memorizing Transformer 相比，RMT 的独特优势是 完全不修改 backbone，适合作为任意预训练模型的 plug-in。

LONGNET: Scaling Transformers to 1,000,000,000 Tokens

问题动机

序列长度是 Transformer 的最后一个原子维度。更长的上下文意味着更大的接收野、更复杂的因果推理路径、以及 in-context learning 的极限探索。然而现有方法要么计算复杂度过高（vanilla attention O(N^2d)），要么牺牲模型表达力（RNN/SSM 在常规长度上不如 Transformer），要么丢失长距离回忆能力（sliding window / convolution），没有任何方法曾扩展到 10 亿 token 级别。

核心想法

提出 dilated attention（膨胀注意力）：attention 覆盖范围随 token 距离呈指数扩展。近距离 token 做精确的 dense attention，远距离 token 做稀疏的采样 attention。多个不同 (w, r) 配置的 dilated attention 组合在一起，实现 线性复杂度 O(Nd) 和 对数级 token 依赖 O(\log N)，同时保持 drop-in 替换 vanilla attention 的能力。

方法细节

Dilated Attention

将输入 (Q, K, V) \in \mathbb{R}^{N \times d} 按 segment 长度 w 切分，然后以间隔 r 做稀疏采样：

\widetilde{Q}_{i} = [Q_{iw}, Q_{iw+r}, Q_{iw+2r}, \ldots, Q_{(i+1)w-1}]

对稀疏化后的 segment 做标准 attention：

\widetilde{O}_{i} = \text{softmax}(\widetilde{Q}_{i} \widetilde{K}_{i}^{T})\widetilde{V}_{i}

多个 dilated attention 按 attention softmax 的分母加权融合：

O = \sum_{i=1}^{k} \alpha_i O|_{r_i,w_i}, \quad \alpha_i = \frac{s_i}{\sum_j s_j}

w 和 r 设为等比数列，使 attentive field 呈指数扩展：

w = \{w_0, w_1, \ldots, N\}^k, \quad r = \{1, r_1, \ldots, r_k\}^k

计算复杂度

方法 复杂度
Recurrent O(Nd^2)
Vanilla Attention O(N^2d)
Sparse Attention O(N\sqrt{N}d)
Dilated Attention O(Nd)

具体推导：

\text{FLOPs} = 2w_0 Nd \sum_{i=0}^{k-1} \frac{1}{\alpha^i} \leq \frac{2\alpha}{\alpha - 1} w_0 Nd \quad (\alpha > 1)

Token 之间的最大路径长度为对数级：

L \approx \log_{\alpha} \frac{N(\alpha-1)}{w_0}

Multi-Head Dilated Attention

不同 head 在稀疏采样时使用不同的偏移量 s_j = j \mod r，确保集体覆盖所有位置，避免信息盲区。

分布式训练

利用线性复杂度，沿序列维度做分布式切分。短 segment（w_i \leq l，l 为每设备序列长度）本地计算；长 segment 先用 all-gather 收集经稀疏化的 KV，再做 cross-attention。由于稀疏化后 \widetilde{K}, \widetilde{V} 大小与总序列长度无关，通信开销为常数。

关键结果

Runtime 扩展

Dilated attention（基于 FlashAttention 实现）在序列长度从 8K 扩展到 1B 时 runtime 几乎保持常数，而 vanilla attention 呈二次增长。分布式算法使单机无法处理的超长序列得以跨多 GPU 训练。

语言建模

在 The Stack（300+ 编程语言）上训练 base-size 模型（768 hidden, 12 heads, 12 layers），LongNet 在所有测试长度上一致优于 Sparse Transformer：

模型 训练长度 2K PPL 8K PPL 32K PPL
Transformer 2K 4.24 5.07 11.29
Sparse Transformer 32K 5.15 4.00 3.64
LongNet 32K 4.37 3.33 3.01

Scaling Law

LongNet 在更大的上下文长度下训练能更高效地降低 test loss，且依然遵循计算量-性能的 power law scaling。从 125M 到 2.7B 参数，LongNet 的 scaling 行为与 dense Transformer 一致，说明 dense attention 不是 scaling 的前提条件。

长上下文 Prompting

随着 prompt 长度从 2K 增加到 32K，test loss 持续下降，证明 LongNet 能有效利用长上下文信息。

局限与延伸阅读

  • 仅在代码数据上验证：The Stack 是代码数据集，自然语言的长距离依赖模式可能不同。
  • 稀疏近似的信息损失：远距离 token 之间的交互被采样近似，对需要精确长距离 recall 的任务可能不足。
  • 仅验证到 base-size：2.7B 是最大模型，更大规模的 scaling 行为有待验证。
  • 与 RMT（segment-level 递归）和 Infini-attention（线性 attention 压缩记忆）相比，LongNet 在 attention pattern 层面做稀疏化，不引入额外的 memory 机制，是更"正交"的加速方案。
  • 与 Compressive Transformer 的区别：后者仍是 FIFO 丢弃旧 memory，而 LongNet 保持对全部 token 的（稀疏）访问。

Leave No Context Behind: Efficient Infinite Context Transformers with Infini-attention

问题动机

Transformer 的 attention 机制在 memory footprint 和计算时间上都是 O(N^2) 的。例如一个 500B 参数模型在 batch size 512、context length 2048 时，KV states 占 3TB 内存。现有的长上下文方法要么丢弃旧 segment（TransformerXL、Compressive Transformer），要么需要不断增长的存储（Memorizing Transformer 的 262K KV 对），要么依赖大量 soft-prompt（RMT、AutoCompressor）。

能否用一个固定大小的压缩记忆（compressive memory）实现无限长上下文？

核心想法

在每个 attention layer 内同时维护 local dot-product attention（处理当前 segment）和 compressive memory（用 linear attention 存储全部历史），通过 learned gating 融合两路信息。Memory 以增量方式更新，不丢弃旧信息，实现 bounded memory + unbounded context。

方法细节

Infini-attention 结构

核心流程（单个 attention head）：

1. 从压缩记忆检索（Memory Retrieval）：

A_{mem} = \frac{\sigma(Q) M_{s-1}}{\sigma(Q) z_{s-1}}

其中 M_{s-1} \in \mathbb{R}^{d_{key} \times d_{value}} 是关联记忆矩阵，z_{s-1} \in \mathbb{R}^{d_{key}} 是归一化项，\sigma 是 element-wise ELU+1 激活函数。

2. 更新压缩记忆（Memory Update）：

Linear 规则：

M_s \leftarrow M_{s-1} + \sigma(K)^T V, \quad z_s \leftarrow z_{s-1} + \sum_{t=1}^N \sigma(K_t)

Delta 规则（先减去已有值再更新，避免重复绑定）：

M_s \leftarrow M_{s-1} + \sigma(K)^T \left(V - \frac{\sigma(K) M_{s-1}}{\sigma(K) z_{s-1}}\right)

3. 长短期信息融合（Gating）：

A = \text{sigmoid}(\beta) \odot A_{mem} + (1 - \text{sigmoid}(\beta)) \odot A_{dot}

每个 head 仅增加一个 scalar 参数 \beta，控制长期记忆与局部 attention 的权衡。

与其他方法的对比

模型 Memory 占用 上下文长度 Memory 更新
TransformerXL (d_k + d_v) \cdot H \cdot N \cdot l N \times l 丢弃
Memorizing Transformer (d_k + d_v) \cdot H \cdot N \cdot S N \times S 无
RMT d_{model} \cdot p \cdot l \cdot 2 N \times S 丢弃
Infini-Transformer d_k \cdot (d_v + 1) \cdot H \cdot l N \times S 增量更新

Infini-Transformer 的 memory 大小与序列长度 完全无关。

Gating 行为分析

训练后出现了两类 attention head：

  • Specialized heads（\beta 接近 0 或 1）：专注于 local attention 或 long-term memory
  • Mixer heads（\beta 接近 0.5）：同时聚合两路信息

每层至少有一个 short-range head，保证输入信号的前向传播。

局限与延伸阅读

  • Linear attention 的表达能力：压缩记忆本质上是 linear attention 的变体，在需要精确 token-level 检索的任务上可能不如显式 KV 存储。
  • 仅在 1B 和 8B 模型上验证：大规模 LLM 上的 continual pre-training 效果有待验证。
  • 与 Compressive Transformer 的根本区别：Compressive Transformer 仍然丢弃旧 memory，而 Infini-attention 通过 增量更新 永不丢弃（bounded parameters + unbounded context）。
  • 与 RMT 的区别：RMT 将记忆编码在 soft-prompt token 中（需要增加 token 数才能提高容量），而 Infini-attention 将记忆编码在 关联矩阵参数 中（固定大小）。

FINCH: Prompt-guided Key-Value Cache Compression for Large Language Models

问题动机

LLM 在 RAG、对话、ICL 等应用中需要处理越来越长的输入上下文，带来两个核心问题：

  1. Context window 限制：超出训练时设定的最大位置编码长度后模型无法工作
  2. KV cache 内存爆炸：OPT-175B 模型本身 325 GB，但 KV cache 需要 950 GB（batch=128, seq=2048）

现有压缩方法要么需要 额外训练/fine-tuning（如 Gist Token、AutoCompressor），要么需要 调用外部模型 做压缩（如 LLMLingua）。能否 不训练、不依赖外部模型，直接利用模型自身的 attention 权重做 KV cache 压缩？

核心想法

在 Prefill 阶段，将长文档分 chunk 逐块处理。对每个 chunk，利用 prompt query 对 document key 的 attention score 来识别最相关的 KV pair，仅保留这些 pair 到 cache 中。关键洞察：attention score 天然反映了 prompt 对文档中每个 token 的关注度，无需额外模型或训练。

方法细节

整体流程

  1. Document Segmentation：长文档被切分为大小 m 的 chunk
  2. 逐 chunk 处理：每步将当前 chunk + prompt + 上一步的 compressed KV cache 一起送入模型
  3. Layer-wise Top-r Selection：在每一层独立计算 prompt-guided attention score，选择最重要的 KV pair
  4. Cache 管理：选中的 KV pair 重新编排位置编码后存入 cache
  5. Generation：最终的 compressed KV cache 用于自回归生成

Prompt-Guided Selection

对于 attention scores 矩阵 \mathbf{A}^{(l)} \in \mathbb{R}^{H \times M \times N}（H 个 head，M 个 query position，N 个 key position），处理步骤：

  1. Head 聚合：求和所有 head 的 attention score
A^{(l)sum}_{ij} = \sum_{h=1}^{H} A^{(l)}_{hij}
  1. 提取 prompt 子矩阵：只看 prompt token 对 document token 的 attention
A^{(l)cont}_{i,j} = A^{(l)sum}_{m+i,j}, \quad i \in \{1, \ldots, n^{que}\}, \; j \in \{1, \ldots, m+c\}

  1. 位置偏差归一化：消除 causal mask 导致的位置偏差

  2. Top-r 选择：对 prompt 维度求和后取 top-r

\mathbf{t} = \text{top-r}(\mathbf{A^{(l)agg}}, r)

其中 r 在每次迭代中动态更新：r_{it+1} = \frac{m_{it+1}}{\sigma} + c_{it}。

Attention 可视化

可视化清晰展示了：prompt "Where was Napoleon born?" 引导模型在文档中找到 "Paris" 相关 token，跨 chunk 迭代逐步压缩，最终生成正确答案。

Slipstream: Trajectory-Grounded Compaction Validation for Long-Horizon Agents

问题动机

长 horizon LLM agent 在执行过程中不断积累上下文，现有系统（Anthropic、Microsoft）通过 synchronous compaction 定期总结来控制上下文长度。但同步 compaction 有两个根本缺陷：

  1. 延迟开销：阻塞式总结占端到端 wall time 的 26-44%。
  2. 静默准确率下降：compactor 必须在不知道 agent 未来需要什么信息的情况下做总结决策。一旦总结替换了原始上下文，后续所有行为都以总结为条件——没有独立信号来验证总结是否正确。

传统摘要评估指标只看当前上下文和候选摘要，无法捕捉 摘要对未来 agent 行为的影响。

核心想法

异步执行是获取 validation signal 的唯一方式：让 compactor 和 agent 并行运行——agent 在原始（未压缩）上下文上继续执行，compactor 同时生成摘要。两者从同一个 pre-compaction 输入独立生成输出，agent 的后续行为（next-k trajectory）可以作为 held-out validation signal 来检验摘要质量。

方法细节

系统架构

Slipstream 的执行流程：

  1. 触发 compaction：上下文达到 threshold \tau
  2. 异步分叉：agent 在原始上下文上继续执行（产生 next-k trajectory），compactor 在另一个线程上并行生成摘要
  3. Trajectory-grounded judge：compactor 完成后，judge 对比候选摘要与 next-k trajectory
  4. Accept / Reject + Update：
    • Accept（绝大多数情况）：切换到压缩后的上下文 + next-k 步骤
    • Reject（1.0-8.5%）：基于 judge 的诊断做 targeted update，修复特定的遗漏或错误，无需重新做完整压缩

有限窗口为何足够

compaction error 在 agent 行为中 很快就会显现：

  • BrowseComp：97% 的首次 error 在 k=1 就出现，100% 在 k=2
  • SWE-bench Verified：60% 在 k=1，88% 在 k=3，96% 在 k=6

Slipstream 的异步窗口平均覆盖 2.1 步（BrowseComp）和 3.7 步（SWE-bench），足以捕获绝大多数 error。

两层验证

Judge 执行两个互补检查：

  1. Statement-level check：摘要是否保留了 next-k trajectory 中显式使用的 具体事实、约束、中间结果和工具观察

  2. Plan-level check：摘要是否支持与原始 continuation 相同的 前向意图（agent 通常会显式表达计划）

这两个检查独立失败的场景不同：摘要可以保留所有事实但改变意图，也可以保留意图但丢失关键事实。

系统优化

  • KV cache 共享：agent 线程和 compactor 线程共享 pre-compaction 上下文的 prefix cache
  • Multi-layer cascade attention：prefix 只加载一次，两个线程共享
  • Judge 开销极小：judge 的输入仅为压缩上下文大小的 3.6-6.8%

Slipstream 将 compaction 从关键路径上移除，减少 11.3-39.7% 的端到端延迟。compaction 越频繁（threshold 越低），相对加速越明显。

  • Async-only（异步执行但不验证）：获得大部分延迟收益，但准确率与 Sync 基本持平
  • Full Slipstream：延迟收益 + 准确率提升 6.4-8.8%

即使用更小的 judge 模型（Qwen3.5-2B 或 Llama-3.2-3B 替代 Qwen3.5-9B），准确率提升仍然显著。说明 validation signal 的价值来自 trajectory-grounded 的方法论本身，而非强 judge 模型。

局限与延伸阅读

  • Rejection 后的 targeted update 有上限：结构性偏移过大时无法局部修复，需 fallback 到同步压缩。
  • Window 外的 error 无法恢复：少数在异步窗口之外才显现的 error（SWE-bench 上 ~4%）与同步 baseline 一样无法挽回。
  • 仅验证两个模型：Qwen3.5-9B 和 Seed-OSS-36B-Instruct，更大模型和更多 workload 的泛化性有待验证。
  • 与 Parallel Compaction 互补：后者解决 输出量控制 问题（通过 block 数量），Slipstream 解决 总结质量验证 问题（通过 trajectory-grounded judge）。两者可以组合使用。
  • 与 Memorizing Transformer / Infini-attention 等 model-level 方法的区别：Slipstream 在 serving system 层面工作，不修改模型权重，适用于任何 LLM backbone。

Parallel Context Compaction for Long-Horizon LLM Agent Serving

问题动机

长 horizon LLM agent（如多步 QA、代码编辑、多轮对话）在执行过程中不断积累上下文，导致：推理延迟随序列增长、超出 context window、以及 "lost in the middle" / "context rot" 导致推理质量下降。

Sequential compaction（同步阻塞式总结）是目前生产系统（Claude Code、Codex、LangChain、LlamaIndex）的标准做法，但存在三个根本问题：

  1. 输出量与输入无关：输入从 2K 增长到 96K（48×），输出仅增长 ~3×。96K 输入时仅保留 ~3% 的信息。
  2. Prompt 指令无效：从 "concise" 切换到 "very detailed"，输出长度几乎不变——模型有内化的 summary 长度先验。
  3. 阻塞代价高：同步 compaction 可占端到端 wall time 的 62%。

核心想法

将长上下文按 固定大小 block 切分，每个 block 由一个独立 worker 并行总结。通过 block 数量（而非 prompt 指令）直接控制总结输出量。关键设计：prefix-aware target-at-end layout——每个 worker 看到从开头到自己 block 的完整前缀，target block 放在最后用 XML marker 标记，兼顾跨 block 上下文理解和 prefix cache 复用。

方法细节

三阶段流程

当上下文超过 threshold \tau 时：

  1. Snapshot & Partition：复制当前对话 \mathcal{X}，切分为 N = \lceil |\mathcal{X}| / B \rceil 个 block

  2. Dispatch：对第 k 个 worker，构建 prompt = blocks 1 \ldots k，其中 block k 用 <TARGET_BLOCK>...</TARGET_BLOCK> 标记。所有 N 个 prompt 并发发送到 vLLM

  3. Merge：按 block 顺序拼接所有 per-block summary，替换原始 history

Sequential Compaction 的基本公式

\hat{\mathcal{H}}_t = \text{LLM}_{\text{compact}}(\mathcal{H}_t \oplus p_c)

其中 p_c 是 compaction 指令 prompt。

Prefix-Aware 布局的优势

设计 Prefix Cache 跨 Block 上下文 问题
Independent chunks 不可用 丢失 每个 worker 只看自己的 block
Shared full prefix 不可用 完整 每个 worker 的 marker 在不同偏移
Target-at-end 可复用 完整 无

Block 数量控制输出量

Threshold \tau 和 block size B 共同决定 worker 数量。在 \tau = 96K 时：

  • B = 16K → 6 个 worker
  • B = 4K → 24 个 worker

通过调节 B，operator 可以将 compaction 输出从 ~25% 扩展到 ~50% 的原始上下文（再配合 prompt 微调）。

输出不变性的实证

跨 4 个 backbone（8B-120B，dense/MoE，reasoning/non-reasoning），输入从 2K 到 96K 增长 48×，输出仅增长 ~3×。切换 prompt 从 "concise" 到 "very detailed" 几乎无影响。

关键结果

准确率随 block size 提升

Block size 越小（worker 越多），总结保留的信息越多，准确率越高。在 100K 上下文的压缩测试中，parallel compaction 在所有 backbone 上一致超过 sequential baseline。

  • \tau = 16K：62.4%（15 次 compaction）
  • \tau = 96K：14.5%（2 次 compaction）

Throughput 提升

在匹配 decode token 量时，parallel compaction 减少端到端 wall time 并提升 compaction throughput。小 block size（4K）是最佳工作点：CV 最低（19.8%-34.1%），cosine similarity 最高（0.65-0.83），兼顾稳定性和效率。

Prompt 敏感性恢复

Sequential compaction 下 prompt 几乎无效，但 parallel compaction 下 prompt 重新生效——给 operator 两个独立控制旋钮：block size 控制粗粒度输出量，prompt 控制每个 block 内的详细程度。

局限与延伸阅读

  • 仅做 characterization：本文不提出新方法，而是系统性地刻画 sequential 和 parallel compaction 的行为，为后续优化提供实证基础。
  • No information quality evaluation：只测量了输出量和 wall time，缺少对总结质量（如 faithfulness、key fact retention）的评估。
  • 固定 block size：未探索 per-block 动态大小（如根据内容类型调整）。
  • 同步阻塞：parallel 的多个 worker 仍需等最慢的完成，异步版本（agent 继续执行、后台压缩）是作者提出的 future work。
  • Slipstream（Trajectory-Grounded Compaction Validation）正好解决了本文提出的异步 compaction 问题，并引入 trajectory-grounded judge 来评估总结质量。
  • 与 FINCH 等 KV cache 压缩方法的区别：本文在 文本层面 做总结（human-readable、model-agnostic），而 FINCH 在 latent space 做选择性保留。
